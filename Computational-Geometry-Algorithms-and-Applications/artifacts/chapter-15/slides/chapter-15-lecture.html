Visibility Graphs

Euclidean shortest paths among polygonal obstacles become shortest paths in a finite graph of mutually visible vertices.

Chapter Goal

Reduce a continuous shortest-route problem to a graph problem whose vertices are obstacle corners plus start and goal.

Algorithmic Core

Build \(G_{\mathrm{vis}}(S^*)\), weight each edge by Euclidean length, then run Dijkstra.

Why The Old Road Map Fails

Feasible Path

The old road map proves reachability using trapezoid centers and separator midpoints.

Good Path

Weighted search on that same graph still misses routes whose bends occur at obstacle vertices.

Design Question

Which finite graph is rich enough that its shortest route is the real Euclidean shortest route?

Road maps for feasibility need not preserve Euclidean length2 / 16
Contrast feasibility with optimality. The Chapter 13 road map is excellent for proving that some route exists, but its graph vertices are trapezoid centers and extension midpoints, so weighted graph search is still restricted to artificial detours. The point of this slide is not that the old road map is wrong; it solves a different problem. For Euclidean shortest paths, the graph must contain the places where an optimal path can actually bend.

Model Assumptions

Point Robot

A point moves in the plane among disjoint simple polygonal obstacles with total edge count \(n\).

Open Obstacles

Collision means intersecting obstacle interiors. Touching a boundary or sliding along it is allowed.

Shortest May Not Be Unique

Symmetric layouts can give two equal minimum-length routes. The algorithm returns a shortest route, not a canonical one.

Feasibility Check

Start and goal are in free space. Every displayed edge is checked against obstacle interiors.

Open obstacles make boundary contact legal and shortest paths attainable3 / 16
State the modeling choices before proving anything. Obstacles are disjoint open polygons, so touching a boundary is allowed and a shortest path can exist. The start and goal lie in free space, and the phrase shortest path means minimum Euclidean length among collision-free curves. Non-uniqueness is not a pathology here; symmetric obstacle layouts can offer two equal routes, and the algorithm only needs to return one shortest route.

Rubber-Band Lemma

Lemma 15.1, In Working Form

Every inner bend of a shortest collision-free path is an obstacle vertex.

Local Shortcut Test

If a neighborhood around the bend is free, a straight chord is shorter and still feasible.

Edge-Interior Turns Also Fail

A half-disk in free space gives the same shortcut when the turn lies along an obstacle edge.

Shortest paths are locally shortest in every small feasible neighborhood4 / 16
Use the rubber-band picture as the proof engine, but keep it local. If a candidate shortest path wiggles through an empty disk, the chord across the disk is shorter and still feasible. If the path turns at a point in free space or along the relative interior of one obstacle edge, a small disk or half-disk gives the same shortcut. The only places a genuine bend can survive are obstacle vertices.

Obstacle Vertices Are Enough

Finite State Set

\(S^* = V(S) \cup \{p_{\mathrm{start}}, p_{\mathrm{goal}}\}\)

Candidate Route

A shortest route is a polygonal chain whose inner vertices are drawn from \(V(S)\).

Geometric Certificate

Each segment between consecutive route vertices must be visible: its relative interior avoids obstacle interiors.

The continuous problem now has a discrete candidate set5 / 16
This slide converts the lemma into a finite state space. Between two consecutive bends the shortest path must be a straight segment, and every inner bend belongs to the obstacle vertex set. That means the continuous curve search can be replaced by a search over visible pairs of special points. The start and goal are added as special points even though they are not obstacle vertices.

Visibility Graph Definition

Definition

Vertices \(v,w\in S^*\) are adjacent in \(G_{\mathrm{vis}}(S^*)\) when segment \(vw\) avoids the interior of every obstacle.

Always Included

Endpoints of the same obstacle edge see each other because boundary contact is allowed.

Blocked Pair

A segment that crosses an obstacle interior is not a graph edge, even if both endpoints are valid states.

Graphundirected
Loopsnone
Max edges\(\leq {m\choose 2}\)
Visibility means no obstacle interior lies between the endpoints6 / 16
Define visibility with the boundary convention in view. Two vertices are adjacent when their connecting segment avoids obstacle interiors; crossing an interior blocks the edge, while following an obstacle boundary is allowed. This is why every obstacle boundary edge belongs to the visibility graph. The graph is undirected, has no self-loops, and after start-goal augmentation it contains the first and last segments of any shortest path.

Shortest-Path Pipeline

Correctness Hook

Lemma 15.1 and the visibility definition ensure every shortest path is represented in the graph.

Optimization Hook

Positive Euclidean weights make the final step a standard weighted shortest-path problem.

Output

A polygonal chain through visible vertices; rendering the chain is just following the predecessor tree.

Continuous geometry feeds a weighted graph algorithm7 / 16
Walk the class through the algorithmic pipeline. First construct the visibility graph on obstacle vertices plus the start and goal. Then assign every edge its Euclidean segment length. Finally run Dijkstra from start to goal. The sanity check on the slide is important because it ties the drawn route back to computation: summing the shown segment lengths agrees with the graph shortest-path distance to numerical tolerance.

Runtime Overview

Naive Visibility

Testing each pair against all obstacles costs \(O(n^3)\).

Sweep-Based Visibility

One pivot sees all visible vertices in \(O(n\log n)\).

Full Graph

Repeat over \(n\) pivots: \(O(n^2\log n)\), with at most quadratic many edges.

Dijkstra Term

For \(k\) visibility edges, graph search is \(O(n\log n+k)\) with the appropriate queue.

The graph can be quadratic; the chapter removes the extra factor of n8 / 16
Separate the two cost centers. The visibility graph can have quadratically many edges, so even storing all candidate visibility edges already suggests a quadratic barrier for full-graph methods. Once the graph is built, weighting edges is quadratic and Dijkstra is linear in the number of edges up to a priority-queue term. The chapter's main construction effort is therefore the faster visibility graph computation.

One Pivot Point \(p\)

Input To One Sweep

A pivot \(p\) and the full obstacle set \(S\). The pivot may be an obstacle vertex or start/goal point.

Sorted Events

Vertices are ordered by clockwise angle from the positive x-axis; equal angles use increasing distance.

Check Against Brute Force

For fixed \(p\), sweep output should match direct segment-obstacle visibility tests.

A useful order lets one visibility test inform the next9 / 16
Now zoom into one call of VISIBLE_VERTICES. Fix a pivot p and sort all obstacle vertices by clockwise angle around p, breaking ties by distance from p. This ordering is the useful memory of the sweep: when several vertices lie on the same ray, nearer vertices are handled first, so their visibility result can help classify farther collinear vertices without rechecking the entire segment from scratch.

Rotating Sweep Status

Status Tree \(T\)

Stores obstacle edges intersected by the rotating half-line \(\rho\), ordered by distance from \(p\).

First Blocker

The leftmost leaf is the nearest edge on \(\rho\); it is the first candidate obstacle that can hide the event vertex.

Invariant

Status order equals direct ray-intersection distance order after every event update.

The rotating ray turns visibility into a nearest-intersection query10 / 16
Introduce the rotating half-line as the analogue of a sweep line. At any instant, the status tree stores exactly the obstacle edges cut by the ray, ordered by distance from p along that ray. The leftmost status edge is the first possible blocker. The check shown on the slide is the invariant to maintain: tree order must match direct geometric intersection distance order at every event.

Event Updates

Only incident edges enter or leave at a vertex event11 / 16
At an event vertex, visibility is tested before the status is updated for the next angular interval. Edges incident to the event that lie on the clockwise side enter the tree; incident edges on the counterclockwise side leave. The three frames show why the update is local: only the two incident obstacle edges can change their relation to the rotating ray as it passes through the vertex.

Normal Visibility Test

Common Case

No earlier event vertex lies on segment \(pw_i\).

Blocked

If the closest status edge intersects \(pw_i\) before \(w_i\), the vertex is hidden.

Visible

If no such edge exists and the local incident wedge is outside obstacle interior, add \(w_i\) to \(W\).

One nearest-edge query replaces a scan over all obstacles12 / 16
Give the common case first. If no earlier vertex lies on the same segment from p, then the candidate w is visible precisely when the first status edge does not intersect segment pw before w, and the local wedge at w does not put pw inside the incident obstacle. This avoids scanning all obstacles; one tree lookup and a constant number of geometric predicates are enough.

Collinear Vertices

visible then clear

Segment \(w_{i-1}w_i\) stays outside interiors, so \(w_i\) remains visible.

visible then inside

The small continuation enters an obstacle interior, so the farther vertex is not visible.

visible then crossed

A status edge intersects \(w_{i-1}w_i\); the farther vertex is blocked.

previous invisible

If \(w_{i-1}\) is hidden, every farther tied vertex on the same ray is hidden too.

Tie handling is a correctness condition, not a sorting detail13 / 16
Collinearity is where careless implementations lose correctness. Because tied vertices are processed by increasing distance, the previous vertex on the ray is already classified. If the previous one is invisible, the farther one is invisible. If the previous one is visible, only the small segment between the two needs inspection: it may be an allowed boundary continuation, may pass through an obstacle interior, or may be crossed by the current first blocker.

Correctness And Complexity

Theorem Ladder

  • Lemma 15.1: bends occur at obstacle vertices.
  • Corollary 15.2: shortest routes use visibility edges in \(S^*\).
  • Theorem 15.3: shortest point-robot path in \(O(n^2\log n)\).
  • Theorem 15.4: visibility graph in \(O(n^2\log n)\).

Sweep Invariant

At event \(w_i\), \(T\) stores exactly the edges cut by the current ray in their along-ray order.

Correctness is geometric; running time is the sweep accounting14 / 16
Use this as the theorem ladder. The rubber-band lemma limits shortest-path bends to obstacle vertices; the visibility graph captures every segment between consecutive bends; Dijkstra chooses the minimum among all captured polygonal routes; and the rotational sweep computes visible vertices from one pivot in O(n log n). Repeating the sweep for all n pivots gives the O(n squared log n) visibility graph bound and the same order for the full shortest-path pipeline.

Translating Polygonal Robot

Configuration Obstacle

For each workspace obstacle \(P\), compute \(P \oplus (-R)\).

Reduction

A translating robot placement is feasible exactly when its reference point avoids configuration-obstacle interiors.

Theorem 15.5

For a convex constant-complexity robot, the shortest translating path is computable in \(O(n^2\log n)\).

Minkowski sums turn robot motion back into point motion15 / 16
Shift from a point robot back to a translating convex robot. Reflect the robot through the origin and add it to each workspace obstacle by Minkowski sum; a placement point is forbidden exactly when the robot would overlap an obstacle. Once these configuration obstacles are built, the same visibility graph method applies in configuration space. For constant-complexity convex robots, this preserves the O(n squared log n) shortest-path bound.

Beyond The Full Graph

Quadratic Barrier

A full visibility graph may contain \(\Theta(n^2)\) edges, so constructing it already costs quadratic time in the worst case.

Reduced Structures

For convex obstacles, common tangents can replace many visibility edges; visibility complexes store richer ray information.

Other Metrics

Link, rectilinear, combined, and weighted-region metrics change which paths count as short.

3D Warning

In three dimensions, shortest-path bends are not confined to a finite obstacle-vertex set.

The visibility graph is the clean baseline, not the end of the story16 / 16
Close with the limitations and extensions. Constructing the entire visibility graph can be quadratically large in the worst case, so later algorithms and special cases try to avoid irrelevant edges. Convex obstacles allow reduced tangent graphs, visibility complexes package richer ray information, three-dimensional Euclidean shortest paths are much harder because bends are not confined to a finite vertex set, and alternate metrics such as link, rectilinear, and weighted-region costs change what shortest means.
