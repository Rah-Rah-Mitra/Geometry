Problem Setup
segments + axis-parallel rectangle

Windowing Problem Setup With Query Rectangle And Segments

Definition

Store a set \(S\) of line segments. Query with an axis-parallel rectangle \(W\), and report all \(s \in S\) with \(s \cap W \ne \emptyset\).

Reporting Semantics

  • Endpoint inside \(W\).
  • Crossing one or two sides of \(W\).
  • Touching or overlapping the boundary.

Algorithmic Pressure

The answer size \(k\) may be large, so the goal is query time close to search overhead plus \(k\), not a full scan of \(n\) objects.

Windowing = geometric reportingtarget: output-sensitive query time
Set up the formal query. We store a set of segments and receive an axis-parallel rectangle W. The answer contains every segment that touches W, whether the contact is an endpoint inside, a crossing through a side, or a portion lying across the box. This slide makes the reporting target concrete before data structures enter.
Case Split
endpoint reports vs side reports

Endpoint Versus Boundary-Crossing Cases

Endpoints Inside

Treat segment endpoints as points and use rectangular range reporting. A segment with both endpoints inside is marked once.

No Endpoint Inside

If a segment still intersects \(W\), it must cross the boundary or lie along it. The query becomes a set of side-intersection tests.

Design Move

Reduce two-dimensional windowing to point range reports plus segment-side intersection reports.

Lemma 10.1 orientation: endpoints by range reportingremaining work: boundary intersections
Separate the easy reports from the hard reports. If an endpoint lies in W, a point range-search structure can find it, with duplicate suppression for segments whose two endpoints both lie inside. If no endpoint is inside but the segment still intersects W, then the segment must cross the boundary, so the problem turns into side-intersection queries.
One-Dimensional Core
stabbing query

Reduction To Interval Stabbing

Stabbing Query

Given intervals \(I\) on the real line and a point \(q_x\), report all intervals \([a,b]\) with \(a \le q_x \le b\).

Segment Interpretation

A horizontal segment intersects the vertical line \(x=q_x\) exactly when its x-projection contains \(q_x\).

horizontal segment + vertical lineinterval contains query coordinate
For horizontal segments hit by a vertical query line, forget the y-coordinate for one moment and project each segment to its x-interval. A vertical line at x equals qx intersects exactly the projected intervals that contain qx. This is the one-dimensional stabbing problem that interval trees solve.
Interval Tree
split by median endpoint

Interval-Tree Split Node Structure

Partition At Node v

  • \(I_{left}\): intervals fully left of \(x_{mid}\).
  • \(I_{right}\): intervals fully right of \(x_{mid}\).
  • \(I_{mid}\): intervals containing \(x_{mid}\).

Stored Twice

\(I_{mid}\) is kept as \(L_{left}(v)\) sorted by left endpoint and \(L_{right}(v)\) sorted by right endpoint.

Recursive Shape

Left and right subtrees repeat the same construction on \(I_{left}\) and \(I_{right}\).

crossing intervals stored at this nodeleft/right leftovers recurse
Explain the invariant at one interval-tree node. The split value xmid partitions intervals into three groups: completely left, completely right, and crossing xmid. Only the crossing intervals are stored at the node, twice: sorted by left endpoint for queries from the left and sorted by right endpoint for queries from the right.
Interval Tree
one search path

Interval-Tree Query Path

If \(q_x < x_{mid}\)

Scan \(L_{left}(v)\) until the left endpoint is greater than \(q_x\); every earlier middle interval contains \(q_x\).

Then Recurse Left

Intervals completely right of \(x_{mid}\) cannot contain \(q_x\), so exactly one child remains relevant.

Charging Argument

Cost per visited node is \(O(1+k_v)\); one node per depth gives \(O(\log n + k)\).

monotone list scanone child per level
Walk a stabbing query down one root-to-leaf path. At each visited node, choose the sorted list that makes the stopping test monotone. If qx is left of xmid, scan by left endpoint until intervals start after qx; if qx is right of xmid, scan by right endpoint in the symmetric direction. Then recurse only into the side that can still contain qx.
Performance
output sensitive

Interval-Tree Bounds And Output Sensitivity

Theorem 10.4 Shape

An interval tree for \(n\) intervals uses \(O(n)\) storage, builds in \(O(n\log n)\) time, and reports stabbed intervals in \(O(\log n+k)\) time.

1 nodeper interval storage location
log ntree depth
kreported intervals

Why \(+k\)

The algorithm is allowed to spend time writing the answer. It is not allowed to inspect unrelated intervals.

linear storagelogarithmic navigation plus reported output
State the performance as the payoff for the split invariant. The structure stores each interval at exactly one node, so storage is linear and the tree depth is logarithmic. Query time is logarithmic plus the number of reported intervals because the traversal follows one path and each reported interval is charged where it is emitted.
Back To Windowing
full line is not enough

Vertical Segment Complication

Candidate Is Not Answer

An x-interval containing \(q_x\) only says the horizontal segment meets the full vertical line.

Extra Test

Report the segment only if its height \(y_s\) also satisfies \(q_y \le y_s \le q'_y\).

Consequence

The node list must answer a two-coordinate query on endpoint data, not just a one-dimensional prefix scan.

vertical query segmentx stabbing plus y range
Now restore the second coordinate. A vertical query segment is not the full vertical line, so an interval that contains qx is only a candidate. The segment's y-coordinate must also lie in the query y-range. This is the moment when a one-dimensional list becomes an associated two-dimensional reporting structure.
Associated Structures
dimension lift

Associated Range Trees For Windowing

At Each Visited Node

Middle intervals have already passed the x-test. The associated structure filters the relevant endpoint coordinates by y-range.

Two Choices

  • Range tree: general rectangular report, more storage.
  • Priority search tree: three-sided report, linear storage per associated set.
Windowing Bound

Axis-parallel segment windowing reaches \(O(\log^2 n+k)\) query time with \(O(n\log n)\) storage.

same outer interval treericher local reporting
At every interval-tree node, replace the plain sorted lists by associated structures on segment endpoints. Range trees give the first version, and priority search trees later exploit the fact that the query rectangle is unbounded on one x-side. The point is not a new outer tree; it is the same split tree carrying richer local reports.
Priority Search Trees
three-sided range report

Priority Search Tree Idea

Target Query

Report points in \((-\infty,q_x] \times [q_y,q'_y]\).

Two Invariants

  • Search-tree partition by y-coordinate.
  • Heap priority by smallest x-coordinate in each subtree.

Why It Fits

The query is bounded in y but unbounded to the left in x, exactly the shape exposed by the two invariants.

bounded in yunbounded in x
Introduce the priority search tree as a hybrid. It is search-tree-like in y, because subtrees represent y-ranges, and heap-like in x, because each subtree exposes the point with smallest x-coordinate near its root. That combination is tailored to queries of the form x <= qx and qy <= y <= qy_prime.
Priority Search Trees
split path + heap reports

Priority Search Query Path

Boundary Paths

Search with \(q_y\) and \(q'_y\). Points stored on the two paths are tested directly against the rectangle.

Hanging Subtrees

Their y-range is entirely inside the query slab. Call the heap-style report routine with \(q_x\).

Prune Rule

If the exposed minimum-x point of a subtree is larger than \(q_x\), no point in that subtree can be reported.

two y-searchesx-priority reports inside selected subtrees
Show the query algorithm geometrically. Search for qy and qy_prime to find a split path in the y-search tree. Subtrees hanging between the two paths already have all their y-values inside the query slab, so they only need the heap-style x <= qx reporting subroutine. Points on the two boundary paths are tested explicitly.
Priority Search Trees
linear storage

Priority Search Invariant

Theorem 10.9 Shape

A priority search tree uses \(O(n)\) storage, builds in \(O(n\log n)\) time, and reports three-sided ranges in \(O(\log n+k)\) time.

Search Invariant

Subtrees partition the y-axis, so only \(O(\log n)\) boundary nodes are ambiguous.

Heap Invariant

Every subtree exposes its minimum x-coordinate, enabling fast reporting or pruning for \(x \le q_x\).

associated structure upgradesame query time, less storage than range trees locally
Summarize why the priority search tree improves the associated structures. The y partition keeps the number of boundary nodes logarithmic. The x-priority property lets a rejected heap root prune the entire subtree for the unbounded side query. This yields linear storage and O(log n + k) query time for the special three-sided rectangle.
Caution
filters are not certificates

Bounding-Box Failure Mode

Tempting Shortcut

Store each arbitrary segment by its axis-aligned bounding box and report all boxes hit by the query.

Failure

The box can intersect a query side even when the segment itself misses it. This creates false positives unless the actual geometry is checked.

Correctness Rule

Bounding boxes may filter candidates; they cannot replace the segment-intersection certificate.

arbitrary segments need stronger structureavoid overreporting by geometry
Use the tempting bounding-box shortcut as a warning. For arbitrary segments, a segment's axis-aligned bounding box can intersect the query object even when the segment itself does not. Bounding boxes are useful filters, but they are not correctness certificates; the data structure must preserve the actual crossing geometry.
Segment Trees
canonical decomposition

Segment-Tree Canonical Cover

Skeleton

Sort all interval endpoints and build a balanced tree over elementary intervals between consecutive endpoints.

Canonical Cover

Store an interval in the highest nodes whose ranges are fully contained in the interval.

Bound

Each interval is copied to \(O(\log n)\) canonical nodes; point stabbing follows one search path.

copy intervals deliberatelygain flexible associated structures
Introduce segment trees through canonical decomposition. The skeleton is built from sorted endpoints and elementary intervals. Any stored interval is represented as a disjoint union of canonical node ranges, with only logarithmically many pieces in the balanced tree. Queries then inspect the nodes on one search path.
Segment Trees
disjoint segment windowing

Segment Tree For Disjoint Segments

Outer Structure

Use a segment tree on x-projections. A vertical query visits canonical subsets whose x-slabs contain \(q_x\).

Associated Structure

For disjoint segments inside a slab, vertical order is stable. A sorted structure reports which segments lie between the query endpoints.

Theorem 10.13 Shape

Vertical segment intersection for disjoint segments: \(O(n\log n)\) storage and \(O(\log^2 n+k)\) query time.

non-axis-parallel but disjointactual intersections, not boxes
For disjoint non-axis-parallel segments, the segment tree stores canonical subsets according to x-projection. Each canonical subset can be equipped with a structure ordered by vertical position, because disjoint segments have a stable vertical order over an elementary x-slab. This supports vertical segment intersection queries in O(log squared n plus k) time.

Recurring Pattern

  • Use endpoints for easy window reports.
  • Use stabbing for side intersections.
  • Use associated structures when a second coordinate matters.
  • Use segment-tree copies when intervals must support richer local data.
