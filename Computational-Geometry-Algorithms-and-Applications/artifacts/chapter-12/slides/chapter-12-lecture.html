Open by contrasting two rendering contracts. A z-buffer answers visibility per pixel while drawing, but the painter algorithm wants a global order of fragments so later scan conversion overwrites earlier fragments. The difficulty is that the correct order depends on the viewpoint, so the chapter asks for a preprocessing structure that can deliver the order quickly as the eye moves.

Cycles Force Splits

Failure Mode

Objects can have a cyclic in-front relation. No single unsplit object order can satisfy all overlaps.

Repair

Split objects into fragments. A fragment participates in a smaller, local order where back-to-front traversal is meaningful.

Invariant

Every split must preserve geometry: the fragment ledger counts intersections and the rendered union remains the same scene.

Cyclic depth is why BSP leaves store fragments, not just original objects2 / 16
Show the class why sorting original objects is too optimistic. Three projected surfaces can overlap so that each is in front of another somewhere. Splitting is the algorithmic escape hatch: after enough cuts, the ordering question is asked about fragments whose relative depth is consistent inside the relevant cell.

BSP Definition

Definition

A BSP tree for objects in \( \mathbb{R}^d \) stores at each internal node \( \nu \) a hyperplane \( h_\nu \), the objects contained in it as \( S(\nu) \), and recurses on fragments in \( h_\nu^+ \) and \( h_\nu^- \).

\( h^+ = \{x: a\cdot x + b > 0\},\quad h^- = \{x: a\cdot x + b < 0\} \)

Base Case

A leaf stores at most one object fragment, or is empty. This is the structural promise painter traversal relies on.

The node stores a separator and the fragments lying on it3 / 16
Give the formal definition but keep the operational picture in view. At an internal node, the hyperplane partitions space into a positive and negative side, while fragments lying exactly in the hyperplane are stored at that node. Everything else is clipped to the two side subproblems until leaves contain at most one fragment.

Node Regions

Region Correspondence

The region of a node is the intersection of all half-spaces chosen on the path from the root.

\( R(\nu)=\bigcap_{\mu \prec \nu} h_\mu^{\sigma(\mu,\nu)} \)

Why It Matters

Fragments in a subtree live only inside that region. The same input segment can become several region-local pieces.

Implementation Check

Classify endpoints with tolerance \(10^{-9}\); near-zero signed distance is treated as coplanar to avoid phantom fragments.

A root-to-node path is a signed half-space certificate4 / 16
This slide turns the tree back into geometry. A node is not just an address in a binary tree; it names a convex region cut out by the ancestor choices. The path signs are a certificate, and a robust implementation should use an explicit tolerance when classifying fragment endpoints against split planes.

Auto-Partitions

Candidate Splitters

In the plane, use the full line \( \ell(s) \) containing an input segment \(s\). In 3D, use the plane through an input triangle.

Auto-Partition

A BSP that chooses only these input-supported split lines or planes is an auto-partition.

Tradeoff

The restriction is natural and simple, but it can force many fragments in 3D. Later low-density BSPs loosen the strategy.

Auto-partitions use splitters supported by input fragments5 / 16
Introduce auto-partitions as the first construction rule because it is easy to implement and analyze. The splitter is not the bounded segment itself but the entire line containing it, or in 3D the entire plane through a triangle. This simplicity is also the source of later lower bounds.

Painter Traversal

Traversal Rule

Visit the far subtree first, then fragments stored on the split plane, then the near subtree.

Correctness Intuition

A fragment in the far half-space cannot obscure a fragment in the near half-space for a viewpoint strictly on one side of the split.

Check

Move the viewpoint across \(h_\nu\): the subtree order must reverse exactly when the signed side changes.

Painter order is a viewpoint-side recursion6 / 16
State the traversal as a rendering recipe. If the eye is on the positive side of the split plane, then the negative subtree is farther and must be drawn first; after the coplanar fragments, the positive subtree is drawn. Crossing the split plane reverses that order, which is a clean test for an implementation.

2D BSP Construction

Recursive Line Split

Choose a segment, extend it to a line, cut all crossing segments, and recurse on the two sides.

Fragment Ledger

Four input segments crossing one horizontal splitter produce four extra pieces: \(4 + 4 = 8\) fragments in the local record.

Numerical Predicate

A segment is crossing only when endpoint signs are strictly opposite after the \(10^{-9}\) tolerance.

Construction state: split line, side classification, fragment ledger7 / 16
Walk through the 2D construction as a local operation. Pick the next segment's supporting line, classify every current fragment, split the fragments that cross, and recurse independently. The ledger matters because expected BSP size is really expected fragment count.

Free Splits

Free Split

A split line may cross a current cell without fragmenting any object in that cell.

Useful Split

Useful splits separate or clip fragments; free splits refine space but do not increase the object-fragment count.

Analysis Role

The 3D randomized construction tracks all useful cells, while free splits are allowed because they do not create new triangle pieces.

Fragment count, not only node count, drives the BSP size analysis8 / 16
Use this to separate geometric refinement from object fragmentation. A split can subdivide a region of space while not cutting any stored object. That is free for the fragment bound, and it explains why later algorithms distinguish useful cells from merely refined cells.

Random Order Matters

Randomized 2D BSP

Choose a random permutation of segments and insert supporting lines in that order.

Shielding

A segment inserted earlier can shield another segment from being cut by a later line.

Check

With a fixed seed, repeated trials show the average fragment count growing like \(n\log n\), while particular orders still vary.

Random order is the proof tool and a practical construction heuristic9 / 16
The same geometry can lead to different fragment counts depending on insertion order. Randomization makes the bad alignments hard to sustain across all segments. The computational teaching check is to run several seeded orders and compare their fragment counts with the n log n curve.

Lemma 12.1 Visual Proof

Lemma 12.1

The randomized planar auto-partition creates \(O(n\log n)\) expected fragments.

Shielding Distance

For fixed \(s_i\), a target segment at distance \(k\) can be cut only if \(s_i\) is earliest among \(s_i\), the target, and the \(k\) shields between them.

\( \Pr[\ell(s_i)\text{ cuts }s_j] \le \frac{1}{\operatorname{dist}(s_i,s_j)+2} \)
At most two targets per distance makes the harmonic sum appear10 / 16
Make the probability argument visual. Fix one segment and look along its supporting line. A target at shielding distance k is cut only if the fixed segment is earliest among the target and all intervening shields, giving probability at most one over k plus two. Since only constantly many targets occur at each distance, summing over distances gives a logarithm for each fixed segment.

3D BSP Generalization

Triangles And Planes

In 3D, an auto-partition chooses planes containing input triangles and splits other triangles along intersection segments.

Modified Random Algorithm

The all-useful-cells view inserts a triangle plane and considers only cells where that plane can actually fragment objects.

Predicate Check

Every new triangle-fragment vertex must satisfy the side predicate of each ancestor plane within \(10^{-9}\).

Plane-side predicates replace 2D line-side predicates12 / 16
Move from segments to triangles without changing the mental model. A triangle's supporting plane is the splitter, and any triangle crossing that plane is clipped into polygonal fragments that are triangulated for storage. The numerical check is stronger in 3D: every generated vertex must still satisfy all ancestor side predicates.

3D Zone Argument

Lemma 12.3

The modified 3D randomized BSP has \(O(n^2)\) expected fragments.

Zone-Theorem Idea

When the \(k\)-th triangle plane is inserted, its useful interactions are charged to exterior faces on the triangle \(t_k\)'s zone in the current partition.

Proof Move

Random order spreads the chance that a triangle becomes responsible for a zone boundary over the insertion history.

The 3D proof is a zone-counting argument13 / 16
This is the proof-sketch slide for the 3D upper bound. The current partition cuts space into cells, and the next triangle's plane only matters where it passes through useful cells. The zone theorem controls the number of such boundary interactions, giving an expected quadratic rather than uncontrolled growth.

Quadratic Lower Bound

Auto-Partition Obstruction

Two crossing families of thin rectangles force repeated splitting: each plane supported by one family cuts all rectangles in the other family.

Theorem 12.5

Every set of \(n\) non-intersecting triangles in \( \mathbb{R}^3 \) has a BSP of size \(O(n^2)\), and some configurations require \( \Omega(n^2) \) fragments for any BSP.

grid obstruction: \(G(n_1,n_2)=(n_1+1)(n_2+1)-1\)
Quadratic behavior is not an artifact of a sloppy analysis14 / 16
Emphasize that the bad 3D bound is real. The grid-like rectangle construction shows why auto-partitions can be forced to split one family every time they choose from the other. The chapter then strengthens the message: even unrestricted BSPs have quadratic worst-case examples in three dimensions.

Density And Guards

Density Parameter

The density \( \lambda \) is the smallest number such that every ball meets at most \( \lambda \) objects whose diameter is at least the ball diameter.

Bounding-Box Guards

Use the four bounding-box corners of every object as guards. They summarize where large objects can affect square regions.

Lemma 12.6

If an axis-parallel square contains \(k\) guards in its interior, it intersects at most \(k+4\lambda\) objects.

Witness Check

For every tested square: objects_intersecting_square <= guards_inside + 4*density_bound.

Low-density scenes are measured by local crowding at comparable scales15 / 16
Define density carefully because it is not just the number of objects in a region. A ball only counts objects at least as large as the ball, so the parameter is scale-sensitive. Bounding-box guards then give a finite sample that controls how many objects any square leaf can intersect, with the k plus four lambda lemma as the bridge from guards to objects.

Low-Density BSP Algorithm

Phase 1: Guard-Guided Cells

Split a square until each leaf has at most \(k\) guards. Use an ordinary quadtree split unless one quadrant is heavy; then shrink that quadrant before splitting.

Lemma 12.7

Phase 1 creates \(O(n/k)\) leaves, each intersecting at most \(k+4\lambda\) objects.

Phase 2: Local BSPs

Run the fragment algorithm only on objects meeting each leaf. Double the guessed \(k\) until the leaf-object test certifies the scale.

Final Bounds

Theorems 12.8 and 12.9 give \(O(n\log\lambda)\) for disjoint 2D segments and \(O(n\lambda)\) for disjoint 3D triangles.

Low density turns global BSP construction into many small certified subproblems16 / 16

The guard phase makes leaves whose object counts are controlled by density, and the shrinking step prevents one crowded quadrant from causing a full quadtree explosion. Then the usual BSP construction is run locally.
