Database To Geometry

Range Query Model

A record with numeric fields becomes a point. A query with lower and upper bounds becomes an axis-aligned rectangle.

Answer

Report exactly the points inside the box. The cost target is preprocessing plus query time proportional to search overhead and output size.

2D Example

Q = [x_1,x_2] \times [y_1,y_2]

Motivate the chapter from database queries. A tuple such as salary and age is just a point in the plane, and bounds on each field form an axis-aligned rectangle. The geometric problem is to preprocess the point set so that a rectangle query reports its contents quickly, ideally with time that separates navigation cost from the number of answers.

1D Split Node

Split Node

The first node whose value lies between the two query endpoints separates the left endpoint search from the right endpoint search.

Canonical Subtrees

While descending to x_1, take right siblings that are fully inside. While descending to x_2, take left siblings that are fully inside.

Reporting

Leaves in selected subtrees are reported without testing each ancestor again.

Review the one-dimensional structure because it is the template for everything later. A balanced binary search tree stores the sorted keys. The query interval first finds the split node where the two endpoint searches diverge. From that split, the left descent contributes whole right subtrees and the right descent contributes whole left subtrees.

Output Sensitivity

Search Overhead

Only the endpoint paths require careful navigation. In a balanced tree there are O(\log n) such nodes.

Reported Leaves

Once a canonical subtree is accepted, its leaves are output directly. This work is O(k).

Pattern

T(n,k) = O(\log n + k)

Name output sensitivity early. We do not want a query bound that hides the cost of printing many answers, because reporting k points really takes k time. The useful accounting is navigation plus output: logarithmic work to discover canonical subtrees, then linear work in the number of reported leaves.

Kd-Tree Construction

Recursive Rule

At each node, split the current point set by its median coordinate.

Alternating Axes

Use a vertical line at one level, a horizontal line at the next, then alternate.

Balance

Median choices keep subproblems comparable, so the tree height is logarithmic for distinct split keys.

Introduce kd-trees as a spatial binary tree rather than as a sorted one-dimensional tree. The construction repeatedly cuts the current point set at a median coordinate, alternating between vertical and horizontal cuts. The median keeps the tree balanced, while the changing axis lets the structure adapt to two-dimensional boxes.

Regions Attached To Nodes

Cell Invariant

Each node owns the rectangle of space consistent with the decisions made on the path from the root.

Subtree Meaning

All points in a subtree lie inside that node region, and no point outside the subtree is needed to answer a fully-contained query cell.

Boundary Convention

A consistent side rule for equality prevents points from being lost or duplicated.

Attach geometry to the tree nodes. The root owns the whole bounding rectangle, and each comparison on a search path clips that rectangle by a vertical or horizontal line. This is why a kd-tree can prune: the node region summarizes every point below the node without inspecting them individually.

Kd Query Pruning

Disjoint

If the node region misses the query rectangle, stop immediately.

Fully Contained

If the node region lies inside the query rectangle, report the whole subtree.

Partial

If regions overlap but neither contains the other, recurse into children.

The kd-tree query has three geometric cases. A disjoint node region contributes nothing, so the subtree is ignored. A fully contained node region contributes all its points, so the subtree is reported wholesale. Only partial overlap forces recursion, and the analysis is about bounding how many partial nodes can occur.

Why Sqrt Appears

Line Crossing Bound

A vertical query side crosses only a limited number of kd-tree regions at each relevant depth.

Recurrence Shape

Q(n) = 2Q(n/4) + O(1)

Every two levels, only two grandchildren can be crossed by a fixed vertical line.

Consequence

Q(n) = O(\sqrt n)

A rectangle has four sides, so kd-tree query time is O(\sqrt n + k).

Give intuition for the square-root term rather than only quoting the theorem. Track one vertical side of the query rectangle through the subdivision. After a vertical split and then a horizontal split, the line can cross two of the four grandchildren. This yields the recurrence Q of n equals two Q of n over four plus a constant, which solves to square root n.

Range Tree Idea

Primary Tree

Build a balanced search tree on x-coordinates.

Associated Structures

At every internal node, store the points in that subtree in a secondary structure ordered by y.

Separation Of Coordinates

Use x to choose canonical subsets, then y to filter each chosen subset.

Now contrast kd-trees with range trees. A range tree keeps a primary balanced tree on x, but each internal node also stores an associated structure for the points in its subtree ordered by y. The data structure is larger, but it lets the two coordinate restrictions be handled in a more systematic way.

Canonical Subsets

Decomposition

The x-interval is represented as a disjoint union of subtree point sets.

Count

Each side of the split path contributes at most one sibling per level.

Bound

O(\log n) \text{ canonical nodes}

Use the same split-node picture from one dimension, but emphasize the word canonical. The selected nodes form disjoint subtrees whose union is exactly the x-range. Because a balanced search path has logarithmic length, the decomposition contains only logarithmically many nodes.

2D Range Query Cost

Step 1

Decompose the x-range into O(\log n) canonical nodes.

Step 2

For each canonical node, query its associated y-structure for [y_1,y_2].

Cost

O(\log n) \cdot O(\log n) + O(k)

Derive the two-dimensional range tree query bound by multiplication. The x-search produces logarithmically many canonical nodes. Each canonical node needs a one-dimensional y-range query in its associated structure. Summing those searches gives log squared n, and the actual reported points contribute the plus k term.

Higher Dimensions

Recursive Tree Of Trees

A d-dimensional range tree stores associated range trees of dimension d minus one.

Query Pattern

Choose canonical subsets in the first coordinate, then pass the remaining box query to the associated structures.

Typical Bound

O(\log^d n + k)

with near O(n\log^{d-1}n) storage in fixed dimension.

Generalize the construction carefully. A range tree in d dimensions is a primary tree in one coordinate, with each node storing an associated range tree for the remaining d minus one coordinates. This recursion is elegant in fixed dimension, but students should notice the storage and logarithmic factors accumulating with dimension.

Equal Coordinate Failure

Failure Mode

Equal x or y values can make a split line contain many points. A naive left-or-right rule may break balance or query consistency.

Tie Break

Replace a coordinate by a lexicographic key such as (x,y) or (x,\mathrm{id}).

Query Translation

Translate interval endpoints into the same composite order so closed boxes still include the intended points.

Discuss degeneracy as a correctness issue, not a footnote. If many points share the same x or y coordinate, comparisons at split lines can become ambiguous and balance can suffer. The standard repair is to use a composite coordinate or symbolic tie breaker, and then translate query endpoints consistently so that closed ranges keep the intended inclusions.

Fractional Cascading Warmup

Repeated Searches

Range trees repeatedly binary-search related sorted y-lists.

Bridge Idea

After one full binary search, stored cross-pointers move the position into neighboring lists.

Goal

Pay O(\log n) once, then only constant overhead per visited canonical node plus reporting.

Prepare fractional cascading by naming the wasted work. In an ordinary range tree, many associated y-lists are searched independently, even though the lists are related by the tree. Fractional cascading stores enough linking information that a position found by one binary search can be transferred into neighboring lists with only constant extra work.

Layered Range Tree

Layered Lists

Replace secondary y-trees by sorted arrays enriched with bridge pointers.

Query Saving

One binary search locates the y-range, then pointer transfers follow the canonical x nodes.

2D Bound

For planar orthogonal range reporting, layered range trees achieve O(\log n + k) query time with extra storage.

Connect the warmup to the final data structure. In the layered range tree, nodes store sorted arrays of y-coordinates, and adjacent arrays have bridge pointers. The x search still finds canonical nodes, but the y positions are cascaded through those lists, reducing the planar query overhead from log squared n to log n plus output.

Tradeoff Dashboard

Kd-Tree

space: O(n)
query: O(sqrt(n)+k)

Compact, geometric, and practical for many point sets. Analysis is driven by how query sides cross subdivision cells.

Range Tree

space: O(n log n)
query: O(log^2 n+k)

Separates coordinates cleanly. Canonical x-subsets delegate to associated y-structures.

Layered Range Tree

space: O(n log n)
query: O(log n+k)

Uses fractional cascading to share searches across related sorted lists. Best when fast repeated queries justify the machinery.
