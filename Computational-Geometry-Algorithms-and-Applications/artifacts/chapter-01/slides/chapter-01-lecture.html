What Counts As A Geometric Algorithm

Working Definition

A geometric algorithm converts a spatial question into finite objects, updates a finite state, and branches on geometric predicates.

Inspect The Contract

  • Input model: points, segments, polygons, subdivisions.
  • Primitive predicates: orientation, containment, intersection, distance.
  • State: ordered lists, edge records, search structures.
The finite state is the algorithm's memory of geometryPredicates are where correctness meets computation
Use this slide to define the working pipeline for the whole course. An application suggests a geometric object, the object is reduced to a small set of primitives, and the primitives are organized by a data structure. The point is that a geometric algorithm is not only arithmetic on coordinates; it is a representation choice plus a sequence of certified local decisions.
Convexity
global shape, local segment inspection

Convexity As A Segment Test

Definition

A set \(S\) is convex when for all \(p,q\in S\), the entire segment \(\overline{pq}\) lies in \(S\).

Algorithmic Reading

The test is quantified over infinitely many pairs, but it hints that boundary edges should be certified by side-of-line predicates.

In Chapter 1, this idea becomes a convex hull: the smallest convex container for a finite point set.

Convexity turns a set property into segment containmentThe hull is the finite boundary we can compute
Introduce convexity as a universal segment test rather than as a picture of a rounded object. For every pair of points inside the set, the connecting segment must remain inside. This turns a global-looking shape property into a simple inspection question, and it prepares students for why hull algorithms only need to preserve boundary evidence.
Convex Hull Output
clockwise polygon list

Hull As A Computable Boundary

Finite Output

For a point set \(P\), report extreme vertices as a cyclic list, for example \(h_1,h_2,\ldots,h_k\) in clockwise order.

Why Order Matters

The same vertices as an unordered set do not define edge traversal, inside tests, or the local turn checks used by scans.

Certificate

Every input point lies inside or on the oriented polygon boundary.

Boundary list = geometric object plus traversal conventionInterior points are evidence, not output
Shift from convex sets to the finite output an algorithm can return. The convex hull may be defined as the smallest convex set containing the points, but a program reports a cyclic list of extreme vertices. Emphasize that the clockwise order is part of the answer because later predicates, containment checks, and edge traversals depend on that order.
Translation Gap
infinite definition -> finite certificate

Why The Definition Is Not The Algorithm

Definition

Intersection of all convex sets containing \(P\): elegant, unique, not directly enumerable.

Certificate

A finite boundary list whose oriented edges keep all input points on the interior side.

Design Principle

Keep the definition for correctness; compute a certificate whose verification is finite.

Definitions identify the targetAlgorithms expose a finite witness
Use the contrast between the infinite intersection definition and the finite edge certificate. The mathematical definition explains uniqueness, but it does not say which lines or halfplanes to examine. A hull algorithm succeeds by finding enough boundary witnesses so that every input point is on the allowed side of every reported oriented edge.
First Algorithm
directed pair witnesses and O(n^3)

Slow Convex Hull

Directed Pair Test

for ordered pair (p,q):
scan every r
accept edge if all r lie one side

Cost

\(n(n-1)\) directed pairs times \(O(n)\) witnesses gives \(O(n^3)\).

This is slow, but it makes the edge certificate completely visible.

Brute force is a proof aidThe next algorithm avoids retesting every pair
Present the slow method as a correctness microscope. For each directed pair of input points, test whether all other points lie on the same side. If they do, that directed pair is a hull edge candidate. There are quadratically many pairs and a linear witness scan for each, giving cubic time, which is too slow but very useful for understanding the certificate.
Primitive Predicate
determinant sign = turn direction

The Orientation Predicate

Predicate

\(\operatorname{orient}(a,b,c)=\det\begin{pmatrix} b_x-a_x & b_y-a_y\\ c_x-a_x & c_y-a_y\end{pmatrix}\)

Sign Meaning

  • \(>0\): left turn.
  • \(<0\): right turn.
  • \(=0\): collinear.

Magnitude equals twice signed triangle area.

The determinant is the algorithm's turning sensorIt replaces visual intuition with a branchable test
Make the determinant the first real primitive of the chapter. Its sign says whether the triple turns left, turns right, or is collinear, and its magnitude is twice the signed area of the triangle. This is the bridge from geometry to implementation: the algorithm does not reason with pictures; it branches on this predicate.
Robust Specification
collinear is a real case

Degeneracy Is Not A Footnote

Replacement Rule

When \(\operatorname{orient}(a,b,c)=0\), replace left/right branching with an on-segment or ordering convention.

Typical Choices

  • Keep only endpoints on a hull edge.
  • Keep all boundary collinear points.
  • Break ties lexicographically before scanning.
Degenerate cases define output semanticsThey must be integrated into the proof
Treat collinearity as part of the specification rather than a rare annoyance. When the orientation value is zero, left and right are not valid categories, so the algorithm needs an on-segment or tie-breaking rule. Students should see that degeneracy changes control flow, output conventions, and proof statements, not merely a line of defensive code.
Numerical Robustness
small error, discrete consequence

When Floating Point Breaks Topology

Failure Mode

A predicate value near zero may flip sign under roundoff, so two local decisions can disagree about the same intended line.

Topological Cost

The output can stop being a simple polygon even when all coordinate errors look tiny.

Robustness means preserving the combinatorial decisions required by the proof.

Numerical error becomes structural after branchingPredicates deserve engineering attention
Explain robustness through topology, not just through numeric error. If nearly collinear triples are classified inconsistently, the directed edge graph can acquire crossings, gaps, or repeated boundary decisions that no polygon could realize. The lesson is that a tiny arithmetic perturbation can become a discrete structural error after predicates drive branching.
Faster Hull
sort left-to-right; split chains

Incremental Design Move

Schedule

Sort points lexicographically by \(x\), then \(y\). Add them in that fixed order.

State

Maintain an upper hull chain and a lower hull chain. Each update touches the chain end.

Design Move

Ordered input converts global edge search into local turn repair.

Sorting creates a prefix invariantUpper and lower chains avoid all-pairs search
Now replace the cubic search with a sorted incremental plan. Sorting the points left to right gives a one-dimensional schedule, and the hull boundary splits naturally into an upper chain and a lower chain. The design move is powerful because it limits every update to the current chain end instead of reconsidering every pair of points.

1. Append

2. Inspect Turn

3. Pop

The state is a chain, not just a stackEach pop has a geometric reason
Walk through the stack behavior as an algorithmic state diagram. Append the next point, inspect the last three points, and pop the middle one while the local turn violates the chosen clockwise invariant. Each pop removes a vertex that cannot remain on the final chain once the new point is included, so the state keeps a visible geometric meaning.
Implementation Convention
ties and boundary policy

Handling Equal x And Collinear Runs

Equal x

Sort by \(x\), then \(y\), so vertical stacks enter the scan deterministically.

Collinear Boundary

Choose whether intermediate boundary points are omitted or retained.

Consistency Rule

The scan predicate, output convention, and proof must all use the same tie policy.

Tie-breaking is part of the algorithmBoundary policy changes the returned list, not the convex set
Use this slide to pin down output convention. Equal x-coordinates require a secondary order so the scan has a deterministic schedule. Collinear runs require a choice: keep only endpoints for the minimal hull polygon, or keep boundary collinear points for an inclusive boundary listing. Either convention can be correct if the predicate and proof use the same rule.
Correctness Proof
Theorem 1.1 as invariants

Proof Of Theorem 1.1 As Invariants

Invariant 1

After a prefix is processed, the stored chain is the hull chain of that prefix.

Invariant 2

No unseen point lies in the finished vertical slab, because the input is processed left-to-right.

Invariant 3

Each point is appended once and popped at most once from each chain.

Correctness follows the maintained chain meaningTime follows from one append and limited pops
Frame the theorem proof as three invariants rather than as a block of text. After processing a prefix of the sorted points, the stored chain is the relevant hull chain for that prefix; the empty slab between consecutive processed points prevents hidden future points from invalidating past interior decisions; and each point is appended once and popped at most once, explaining linear scan work after sorting.
Asymptotics
slow n^3 versus sort plus scan

Cost Model

Slow Hull

All directed pairs times all witnesses: \(O(n^3)\).

Incremental Hull

Sort once, then scan upper and lower chains: \(O(n\log n)\).

Design Pattern

Pay for order so local invariants can replace global search.

The scan work is linear after sortingThe proof and cost model share the same stack invariant
Compare the two algorithms on the same axes. The slow method spends work on all directed pairs and all witnesses, leading to cubic growth. The scan pays for sorting and then performs a linear number of stack actions. The point is not just a better asymptotic bound; it is the design pattern of trading global search for an ordered local invariant.
Algorithm Engineering
simplify, integrate, certify

Robustness Design Phases

1. Simplify

Start under general position so the core geometric invariant is visible.

2. Integrate Degeneracy

Add collinear, equal-coordinate, and repeated-point cases to the specification.

3. Robust Predicates

Choose arithmetic or symbolic rules that preserve the proof's combinatorial signs.

Clarity first, completeness next, certified predicates alwaysRobustness is a design phase, not a patch
Connect the chapter's robustness discussion to a disciplined workflow. First simplify the problem under a general-position assumption so the idea is visible. Then integrate degeneracies into the formal cases. Finally choose predicate implementations that preserve the combinatorial decisions the proof assumes. This order keeps clarity without pretending that hostile inputs disappear.
