The chapter is a sequence of reductions: a robot placement becomes a point, collision becomes membership in forbidden configuration space, and continuous feasibility becomes graph reachability in a roadmap.

Modeling Contract

Application Frame

A robot must move from start to goal while avoiding known obstacles in a static environment.

Simplifications

  • Planar work space, polygonal obstacles.
  • Polygonal robot with a chosen reference point.
  • Motion is geometric; dynamics and sensing are outside this model.

Computational Payoff

The problem becomes membership and connectivity in a planar subdivision or in sampled slices of a 3D configuration space.

Modeling is a contract: enough geometry to prove algorithms2 / 16
Use this slide to separate robotics reality from the chapter model. The real application has sensing, dynamics, uncertainty, and actuators. The computational geometry model deliberately freezes the world into known polygonal obstacles and a polygonal robot so that collision-free motion can be studied as an exact planar geometric problem.

Configurations Are Points

Translation Only

\(R(x,y)\) places the robot reference point at \((x,y)\). The configuration space is \(\mathbb R^2\).

Translation Plus Rotation

\(R(x,y,\varphi)\) adds orientation, so \(C(R)=\mathbb R^2 \times S^1\).

Degree Of Freedom

The number of independent parameters needed to specify a placement.

A placement of a region becomes a point in parameter space3 / 16
Define the key abstraction slowly. The work-space robot may occupy a two-dimensional region, but a placement is encoded by a small parameter vector. A translating planar robot has two degrees of freedom, while allowing rotation adds the angle parameter and changes the topology because zero and one full turn are identified.

Free, Forbidden, C-Obstacles

Predicate

\(p \in C_{\mathrm{forb}}\) iff \(R(p)\cap P_i \ne \emptyset\) for some obstacle \(P_i\).

Free Space

The allowed configurations form \(C_{\mathrm{free}} = C(R)\setminus C_{\mathrm{forb}}\).

Touching Convention

Configurations where the robot only touches an obstacle boundary are treated as forbidden, so valid paths live in the open free region.

C-obstacles are obstacle shadows cast into parameter space4 / 16
Make the collision predicate the star of the slide. A configuration is forbidden exactly when the placed robot intersects an obstacle; the C-obstacle is the set of all such parameter points for one obstacle. Mention the convention used here: touching is treated as forbidden, so the planned route stays in the open free region.

Point Robot Free Space

Special Case

For a point robot, the reference point is the robot. Obstacles are already the forbidden region.

Chapter 6 Reuse

Vertical extensions from obstacle vertices produce a trapezoidal map of the free space inside a bounding box.

Preprocess

Expected \(O(n\log n)\) time for the point-robot free-space map.

The first planner is a point-location plus cell-adjacency structure5 / 16
Now reduce to the first algorithmic case. For a point robot, work space and configuration space coincide, so the forbidden region is just the polygonal obstacles. The trapezoidal map from Chapter 6 decomposes the remaining free area by vertical extensions, giving the finite cells that later carry the roadmap nodes.

Roadmap Query

Query Steps

  • Locate the start and goal trapezoids.
  • Attach each point to its cell-center node.
  • Run BFS or shortest-path search in the roadmap graph.

Three Path Pieces

start-to-center, graph route through wall nodes, and center-to-goal.

Query Bound

Point-robot query: \(O(n)\) after preprocessing.

Continuous motion is reported by stitching certified free segments6 / 16
Explain the roadmap path as three geometric pieces. First connect the start point to the center node of its trapezoid, then traverse graph edges through wall nodes and cell centers, and finally connect the goal cell center to the goal. Point location supplies the start and goal cells before the graph search begins.

Roadmap Completeness Proof

Proof State

An arbitrary free path crosses a finite sequence of trapezoids \(\Delta_1,\ldots,\Delta_k\).

Replacement Move

Each shared wall has a roadmap node. Connect cell centers to shared-wall nodes while staying inside the same free trapezoid.

Conclusion

If a continuous free path exists, the roadmap has a graph path connecting the start and goal cells.

Completeness follows from preserving the crossed cell sequence7 / 16
Give the correctness proof as a deformation argument rather than a formal wall of text. Any continuous free path crosses a sequence of trapezoids. Consecutive trapezoids share a vertical wall segment, and the roadmap includes a node on that wall, so the cell sequence can be converted into a graph path without leaving free space.

C-Obstacle Equals Minkowski Sum

Identity

\(C_P = P \oplus (-R)\)

Forward Direction

Collision gives a shared point \(q\). Rearranging \(q = p+r\) places the reference point in \(P\oplus(-R)\).

Backward Direction

A sum witness \(p-r\) says the translated robot point \(r\) lands on obstacle point \(p\), so contact occurs.

Polygonal robots become point robots among inflated obstacles8 / 16
This is the central reduction for a translating polygonal robot. If a placed robot intersects an obstacle, some robot point and obstacle point coincide, which means the reference point lies in the obstacle plus the reflected robot. Conversely, any point in that Minkowski sum gives a contact witness, so the inflated obstacle is exactly the forbidden set.

Convex Minkowski Algorithm

Support Direction View

The extreme point of \(P\oplus Q\) in direction \(d\) is the sum of the extreme points of \(P\) and \(Q\) in direction \(d\).

Edge-Angle Walk

Sort the convex boundaries cyclically by edge angle and merge the two streams. Equal angles advance both.

Check

For small cases, the merged output matches the convex hull of all pairwise vertex sums and has at most \(n+m\) edges.

Convex sums are computed by a cyclic merge, not by all vertex pairs9 / 16
Focus on the edge-angle walk. For convex polygons, the boundary of the sum is obtained by merging the directed edge sequences by polar angle. The support direction viewpoint explains why no more than n plus m edges appear: every output edge advances at least one input edge sequence.

Pseudodiscs

Pseudodisc Pattern

Any two boundaries cross at most twice, so their visible boundary pieces cannot alternate many times.

Where It Comes From

Convex obstacle pieces inflated by the same convex reflected robot inherit controlled support-direction behavior.

Why We Care

This is the combinatorial reason the forbidden-space union can be near-linear rather than all-pairs complex.

Pseudodisc behavior controls the cost of overlaying inflated obstacles10 / 16
Introduce pseudodiscs as the union-complexity hinge. Inflated convex obstacles generated from disjoint convex pieces behave as shapes whose boundaries meet at most twice. The useful intuition is directional: for a fixed direction, the supporting features line up over connected intervals, preventing repeated alternation on the union boundary.

Union Complexity Proof Move

Charge What Survives

Only boundary features that appear on the outer union need to be counted.

Inspectable Bound

For pseudodiscs, crossing vertices on the union boundary are charged to shape vertices and a constant number of boundary transitions.

Algorithmic Consequence

A linear-complexity union is small enough to decompose and query.

Do not count the whole overlay; count the union boundary11 / 16
Make the charging argument inspectable. Boundary crossings that survive on the union can be charged to original vertices and pseudodisc intersections rather than to all pairwise overlays. The punchline for the lecture is that the union is linear in total input complexity, which keeps the later translational planner from exploding quadratically.

Rotation Adds A Cylinder

Topology

\(C(R)=\mathbb R^2 \times S^1\)

Slice

Fixing \(\varphi=\varphi_i\) gives a planar translational planning problem.

New Difficulty

Forbidden-space boundaries curve through the rotation parameter and can change combinatorial type between slices.

The rotation coordinate is cyclic, so zero and a full turn are the same slice13 / 16
Now add the third parameter. The configuration space for a planar robot that both translates and rotates is R squared times a circle, not ordinary three-space. Horizontal slices at fixed orientation are ordinary translational problems, but as the orientation changes the C-obstacle cross-section twists through configuration space.

Slice Roadmaps And Failures

Slice Roadmaps

Compute a trapezoidal roadmap \(G_i\) for each sampled orientation \(\varphi_i\), then connect compatible cells in adjacent slices.

Failure Mode

Endpoint placements in two slices can both be free while the mid-rotation placement intersects an obstacle.

Computational Check

Record intermediate orientations on every inter-slice arc before and after robot enlargement.

Sampling orientation gives a graph, but not an exact planner14 / 16
Use the two-slice picture to explain both the method and its weakness. Within one slice, translational paths are checked exactly. The risky step is connecting nearby slices: both endpoint placements may be collision-free, while an intermediate orientation along the rotation arc collides with an obstacle.

Enlarged Robot And Alternatives

Conservative Repair

Replace \(R\) by a polygon containing the sweep of \(R\) through a half slice step.

Tradeoff

The original robot gains safer rotations, but the enlarged robot may reject a real path.

Planning Landscape

Exact methods improve guarantees; heuristic roadmaps and fields often scale better in high-dimensional settings.

Approximation can create false negatives even when every reported path is safe15 / 16
Discuss the sweep enlargement as a conservative repair. If the robot is replaced by a shape containing the region swept during a half-step of rotation, then accepted inter-slice rotations of the original robot are safer. The cost is false negatives, so the slide also names exact cell decompositions, retraction roadmaps, potential fields, and probabilistic roadmaps as alternative planning philosophies.
