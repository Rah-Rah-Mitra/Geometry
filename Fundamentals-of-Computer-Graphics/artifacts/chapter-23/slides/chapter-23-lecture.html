Chapter 23Visualization as accountable graphics design
Open by defining visualization as a graphics discipline for human judgment. The important contrast is not static versus interactive, but whether a person must compare, explore, explain, or decide. Preview the pipeline from data abstraction through validation so every later technique has a purpose.
Background and resource limits

Visualization Is Needed When Judgment Still Matters

When To Visualize

Use visualization when exploration, hypothesis testing, explanation, or decision support depends on human interpretation.

When It Is Less Central

If a fully specified algorithm can make the decision without human judgment, visualization may be mainly diagnostic or explanatory.

Design Constraint

Every graphic spends limited pixels and limited attention. Showing everything can be worse than showing a disciplined abstraction.

Sections 23.1 and 23.1.2Human attention, computation, display capacity
Use this slide to name the three scarce resources. Computation limits how much data can be processed, human attention limits how much can be inspected, and display capacity limits how much can be shown. Good visualization design balances all three instead of merely drawing more marks.
Data types

Data Types Drive Encoding Choices

Table Fields

Rows are items; columns are attributes. Quantitative, ordered, and categorical attributes support different comparisons.

Relational Fields

Nodes and edges encode connection. The task may be path following, community comparison, or finding bridge nodes.

Spatial And Temporal Fields

Some coordinates are given by the phenomenon itself; others are chosen by the designer to make structure visible.

field type \(+\) task \( \Rightarrow \) channel priority
Section 23.2Quantitative, ordered, categorical, relational, spatial
Before choosing a chart, classify the data. Quantitative, ordered, categorical, temporal, relational, and spatial fields support different operations and different visual channels. The notebook dataset is useful because one synthetic table contains all of these types and makes the classification concrete.
Human-centered design

Translate Domain Questions Into Abstract Tasks

Task Characterization

Interview language is domain-specific. The abstraction layer names reusable operations such as find, compare, filter, summarize, and follow paths.

Why It Matters

Two unrelated domains can share the same data operation, while two questions about the same dataset may need different visual encodings.

Notebook Check

Every abstract task in the generated dependency graph has a path to validation, preventing unsupported design claims.

Sections 23.3.1 and 23.3.2Task abstraction precedes chart choice
Emphasize that domain questions become reusable abstract tasks. A facilities question about inspection becomes find outliers and locate them; a question about failures becomes follow graph paths. This abstraction step is what lets visualization knowledge transfer across scientific, engineering, and operational domains.
Data transformation

Transform Data Before Drawing

Raw Fields

Location, subsystem, hour, load, temperature, vibration, and latency are measured or simulated fields.

Derived Fields

Risk score, ordered status, selected subset, clusters, calibration bins, and PCA coordinates are designed to answer tasks.

Validation Cost

Derived dimensions are powerful, but the deck must also state how they are checked: counts, monotonicity, calibration, or conservation.

raw table \(X\) \( \rightarrow \) derived feature \(f(X)\) \( \rightarrow \) task evidence
Section 23.2.2Derived dimensions are design decisions
The chapter warns against treating raw columns as automatically ready for display. Derived dimensions such as risk score, status, uncertainty, clusters, and principal components often expose the question more directly. The cost is that every transformation needs a recorded validation check.
Visual encoding principles

Marks Carry Data Through Visual Channels

High-Accuracy Channels

Position on a common scale is strongest for quantitative comparison. Length and angle can work, but usually with more effort.

Identity Channels

Hue separates a small number of categories well, especially when categories are not ordered.

Lower-Capacity Channels

Area, opacity, and glyph parts are useful, but they need restraint because viewers compare them less precisely.

Section 23.4.1Marks: points, lines, areas, glyphs
Present marks as geometric carriers and channels as the adjustable properties of those marks. Position is usually the most accurate channel for quantitative comparison, while hue works well for a small set of categories. The slide should make encoding choice feel like a resource allocation problem.
Color and channel fit

Color Must Match The Data Semantics

Categorical Color

Use separated hues for a small set of names: Cooling, Compute, Office, Transit.

Ordered Color

Use monotone lightness for ordered values such as risk or magnitude. The viewer should not need to decode a color wheel.

Notebook Evidence

Sequential map: 0 luminance reversals. Rainbow map: 92 luminance reversals. The problem is perceptual, not just aesthetic.

Section 23.4.2Categorical hue versus ordered lightness
Use the luminance strip to separate category color from ordered color. A sequential map gives a stable lightness order for risk or magnitude, while rainbow hue can reverse perceived order. The notebook check makes this measurable with zero sequential reversals and many rainbow reversals.
Spatial layouts and labels

Use Space Deliberately, Then Add Text Sparingly

Given Space

Maps, floor plans, and fields have spatial meaning before visualization begins. Preserve it unless the task says otherwise.

Chosen Space

For nonspatial data, layout is an encoding decision. Avoid 3D perspective when it adds occlusion without adding task value.

Labels

Text is exact and expensive. It works best for selected items, landmarks, and details on demand.

Sections 23.4.3 and 23.4.42D versus 3D layout; text labels
Explain that spatial layout is either data given by the problem or a visual choice made by the designer. Two-dimensional layouts are easier to inspect than unnecessary 3D, and labels should be staged carefully because text is precise but consumes display and attention quickly.
Interaction principles

Interaction Changes The Question State

Overview First

Show the full set so the viewer can form a mental model of scale, coverage, and rough structure.

Zoom And Filter

Change the viewport or selected subset. The notebook predicate selects 12 of 760 observations.

Details On Demand

Reveal labels, measurements, and uncertainty only when a user asks for the selected item.

Cost

Interaction adds implementation cost and cognitive state. It should support a task, not merely make a graphic feel busy.

Section 23.5.1Overview, zoom/filter, details on demand
Interaction is not decoration; it changes the current data subset, viewport, ordering, or detail level. The canonical pattern is overview first, then zoom and filter, then details on demand. Ask students to identify exactly what state changes after each user action.
Composite and adjacent views

Composition Coordinates Multiple Views

Same Frame

Best when direct comparison is possible without clutter. Superimposing can preserve context but risks occlusion.

Adjacent Frames

Small multiples and linked summaries spend space to reduce memory load and clarify group comparisons.

Notebook Views

Single shared frame, layered focus/context, linked histogram, detail panel, and small multiples share selected items.

Section 23.6Layering, glyphs, multiple views, linked views
A single view is easiest to read when it is sufficient, but complex tasks often need layers, small multiples, or linked panels. The key invariant is consistency: the same selection, axes, categories, and encodings must mean the same thing across the composed views.
Relational examples

Relational Data Needs Two Readings

Node-Link Reading

Good for following a path, seeing local neighborhoods, and explaining a route through the network.

Matrix Reading

Good for dense comparison, avoiding crossings, and seeing block structure after nodes are ordered.

Notebook Check

22 nodes, 45 edges, matrix edge count equals graph edge count, and this node-link layout has 35 crossings.

Sections 23.6 and 23.8.2Graphs: paths, communities, adjacency
Graphs are a good example of why composition matters. Node-link drawings support path following but can accumulate crossings, while adjacency matrices remove crossings and make dense structure easier to compare. Neither representation dominates; the right choice follows the task.
Data reduction

Reduction Is A Declared Tradeoff

Overview And Aggregation

Replace many items with summaries when the task needs pattern before detail.

Filtering And Navigation

Remove irrelevant items or move through data neighborhoods while preserving enough context to stay oriented.

Dimensionality Reduction

Project high-dimensional measurements into a lower-dimensional view, then verify the projection algebra and interpretation.

Section 23.7Aggregation, filtering, focus+context, PCA
When there are too many items or dimensions, reduction becomes unavoidable. Aggregation, filtering, focus plus context, and dimensionality reduction each remove or reshape information. The instructor should ask what is preserved, what is discarded, and which invariant proves the reduction behaved correctly.
Validation and uncertainty

Validation Belongs Inside The Design

Layered Validation

Check the domain question, data abstraction, encoding and interaction technique, algorithm, and generated artifacts.

Uncertainty Encoding

Risk and confidence are not the same signal. Interval width, opacity, or size can reveal when a warning is uncertain.

Notebook Evidence

Calibration mean absolute error is 0.020; interval coverage is 1.0; eight nonblank images and one HTML dashboard are checked.

Section 23.3.4Perception, computation, uncertainty, artifact integrity
Validation happens at several layers, from the domain question to the algorithm and artifact files. Uncertainty should be visible when decisions depend on confidence. The notebook checks calibration, interval coverage, selection semantics, and artifact integrity so claims are backed by evidence.
Examples and design patterns

Examples Are Combinations Of The Same Choices

TablesSort, filter, align, and label values for lookup and comparison.
GraphsChoose node-link or matrix depending on paths, clusters, and density.
TreesExpose hierarchy with containment, indentation, or parent-child links.
MapsRespect geographic position while encoding thematic variables carefully.
Section 23.8Tables, graphs, trees, geographic data, spatial fields
Use the examples as a taxonomy, not as a gallery. Tables, graphs, trees, maps, and spatial fields all combine data types, tasks, encodings, interaction, and reduction differently. The point is to recognize the design pattern behind the example rather than memorize one layout.

End of Chapter 23Visualization as accountable design
Close by making the habit explicit. A visualization is a chain of accountable design decisions: name the data, name the task, choose channels, add interaction or composition only when needed, reduce deliberately, and validate both perception and computation before trusting the display.
