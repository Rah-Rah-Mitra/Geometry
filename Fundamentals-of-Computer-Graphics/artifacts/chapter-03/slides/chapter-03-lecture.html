The important move is not to memorize display hardware, but to notice that an image array can be interpreted by many devices. Raster Model
Array Plus Interpretation

Raster Images Are Device Contracts

Core Abstraction

A raster image is a finite 2D array whose entries are samples or local summaries of an image function.

Device Independence

The same stored values can feed display subpixels, printer dots, sensor reconstruction, texture lookup, or a later image-processing step.

Bug Magnet

Treating an image pixel as identical to a display pixel hides resampling, gamma, quantization, and coordinate convention errors.

Make the abstraction concrete before naming any equations. A raster is not merely a picture on a screen; it is an array plus an interpretation supplied by a device or algorithm. Stress that device independence is useful precisely because later operations can resize, filter, composite, store, and display the same image under different conventions.
Devices
Output And Input

Raster Devices Explain The Array

Displays

Emissive or transmissive pixels use controllable light. Color displays commonly split one pixel into red, green, and blue subpixels.

Hardcopy

Printers may be binary at each grid site or continuous tone. High resolution helps edges and halftone patterns approximate intermediate values.

Input Sensors

Cameras and scanners produce raster measurements. A color-filter mosaic records incomplete color and needs reconstruction before full RGB use.

Use the three device families to motivate why the same word pixel can mean several physical things. Displays control emitted or transmitted light, printers deposit marks or tones, and sensors measure incoming energy. The array abstraction survives these differences, but resolution, color channels, and sampling density must be interpreted through the device.
Pixels
Samples Of A Function

A Pixel Is A Local Sample

\(I(x,y): R \to V\)

Domain

The image occupies a rectangle in 2D coordinates, centered on integer sample locations.

Value Set

The value may be grayscale, RGB, RGBA, integer, floating point, linear light, or encoded display data.

Interpretation

Pixel entries are local measurements or averages. They are not automatically the geometry of the image.

Slow down on the sample convention because it affects every later chapter that maps geometry to pixels. The integer pair names a sample location, while the image domain extends half a pixel beyond the outer samples. This convention lets camera rays, rasterization rules, texture lookups, and filtering kernels talk about the same coordinates.
Coordinates
Rows, Columns, And Origins

Coordinate Conventions Are Part Of The Data

Course Convention

Use \((i,j)\) for column and row. The bottom-left sample is \((0,0)\), and the top-right sample is \((n_x-1,n_y-1)\).

Array Convention

Code often stores rows first, so an array element may be accessed as image[j, i, channel].

API Mismatch

Many file formats and graphics APIs count rows from the top. A correct image pipeline names the origin before trusting orientation.

Emphasize that coordinate conventions are not pedantic details. A vertically flipped texture, a misplaced sample center, or an off-by-one crop can all come from silently switching between row-major array access and screen-space coordinates. Ask students to state origin, axis direction, and sample-center convention whenever they inspect an image.
Pixel Values
Shape, Type, Range

Pixel Values Carry Engineering Commitments

Value Record

Every array should be described by shape, channel count, numeric type, value range, and whether values represent linear light or encoded display codes.

Storage Pressure

A 10 MP RGB image at 32-bit float per channel is about 114.44 MiB before compression or metadata.

bytes = width x height x channels x bytes_per_channel

Tie pixel formats to costs and failure modes. Floating point is attractive because it preserves range and precision during computation, but images are large enough that storage and bandwidth matter immediately. Fixed-range integers are compact and common, yet they force clipping and quantization decisions that should be deliberate rather than accidental.
Color
Additive RGB

RGB Color Is A Point In A Unit Cube

Additive Primaries

Display color is built by adding controlled red, green, and blue light, not by mixing pigments.

Cube Coordinates

Black is \((0,0,0)\), white is \((1,1,1)\), and colors such as yellow occupy corners where two primaries are on.

Quantized In Practice

Eight-bit RGB stores each component as an integer code from 0 to 255, so the cube is sampled on a finite lattice.

Treat the cube as a coordinate system rather than a color theory lecture. Students need enough RGB mechanics to reason about program values: three additive channels, bounded coordinates, corner colors, and finite integer codes. Make the contrast with paint mixing explicit because it prevents the common red-yellow-blue intuition from entering display calculations.
Gamma
Codes Versus Light

Gamma Separates Stored Codes From Emitted Light

displayed intensity \(= M a^\gamma\)
gamma encode: \(a' = a^{1/\gamma}\)

Operational Rule

Decode stored values before lighting or filtering in linear light, then encode again for display or common image files.

Inspection Target

The chapter notebook checks that gamma encoding and decoding round trip, and that half intensity maps to the expected code.

Present gamma as a bookkeeping distinction between code values and physical light, not as an isolated display curiosity. A stored value of one half is not usually half the emitted light. The useful engineering habit is to decode before linear-light operations, perform the computation, and encode only when targeting a display or storage convention.
Gamma Workflow
Where To Compute

Linear-Light Workflows Keep Averages Honest

Pipeline

Stored code values are convenient for files and displays. Lighting, blur, interpolation, and compositing need values proportional to light.

encoded RGB -> gamma decode -> compute in linear light -> gamma encode -> quantize for storage

Common Mistake

Averaging encoded pixel codes can darken or brighten results because the arithmetic is not performed in the same space as light transport.

Connect the gamma curve to actual rendering operations. When students average, filter, composite, or illuminate encoded values, they are doing arithmetic in a perceptual or display code space rather than in light space. The safe pattern is simple enough to remember: decode, compute, encode, then quantize for the chosen output.
Finite Storage
Precision And Range

Quantization And Clipping Are Different Losses

Quantization

Continuous or floating values are rounded to a finite set of levels. The artifact is precision loss, often visible as banding.

Clipping

Values outside the allowed range are clamped. The artifact is range loss, such as saturated highlights with no recoverable detail.

Notebook Check

For 8-bit data, the generated ramp confirms 256 unique values and a maximum absolute error under half a step.

Keep the two storage losses separate. Quantization says there are not enough levels, so nearby values are rounded together. Clipping says values outside the allowed interval are forced to the boundary. A high dynamic range pipeline can avoid clipping during computation, while higher bit depth or dithering can reduce visible quantization.
Compositing
Coverage And Opacity

Alpha Describes How Much Foreground Contributes

\(c = \alpha c_f + (1-\alpha)c_b\)

Coverage Reading

If the foreground covers fraction \(\alpha\) of a pixel, the rest of the pixel contributes background color.

Opacity Reading

A transparent foreground can also be modeled as blocking part of the background and adding its own attenuated color.

Storage Reading

An alpha mask stores coverage separately; an RGBA image stores alpha as a fourth channel beside RGB.

Explain alpha with a physical picture before moving to file formats. At an edge, a pixel may be partly foreground and partly background, so a weighted average is natural. The same equation can also model transparency. What matters computationally is that alpha travels with the color data and states how much foreground participates.
Alpha Representation
Filtering Without Color Leakage

Premultiplied Alpha Stores Contribution Directly

Straight Alpha

RGB stores foreground color even where alpha is small or zero. Filtering may blend invisible colors into visible edges.

Premultiplied Alpha

Stored color is already multiplied by alpha, so interpolation blends actual contributions rather than hidden colors.

Invariant

For an opaque background, straight alpha over and premultiplied over agree when the representation is converted correctly.

This is the slide where alpha becomes a representation issue. Straight alpha is easy to describe, but filtering can accidentally reveal RGB values from nearly transparent pixels. Premultiplied alpha stores contribution instead of unattached color, so interpolation, mipmapping, and soft edges behave more like the over equation intends.
Storage
File Interfaces

Image Storage Freezes A Set Of Choices

Raw Size

An uncompressed 1 MP, 8-bit RGB image stores about three megabytes of sample data before file headers and metadata.

Compression

Lossless formats preserve exact pixel values. Lossy formats trade exactness for much smaller files, often tuned to perception.

Contract Questions

Which channels exist? Are values encoded or linear? Is alpha straight or premultiplied? Is compression allowed to change samples?

Frame storage formats as serialized decisions, not as a list of extensions to memorize. Once an image is saved, many choices become part of an interface with other software: channel order, bit depth, encoding, compression, alpha meaning, and metadata. A robust pipeline writes those decisions down before downstream tools infer them incorrectly.
Notebook Lab
Array Audit

Audit The Image Array Before Saving It

Before Aesthetic Judgment

Ask whether the array facts are coherent: dimensions, axes, channels, dtype, range, encoding, and alpha representation.

Executable Invariants

The chapter notebook checks nonblank artifacts, gamma round trips, quantization bounds, RGB cube corners, and alpha equivalence.

Transferable Habit

A rendered image is easier to debug when each visible artifact can be traced to a numeric contract.

Use the lab as the practical synthesis of the chapter. Before asking whether a picture looks good, the renderer should know what array it produced. The notebook records shape, dtype, value range, encoding, quantization error, alpha range, and artifact existence so a visual result is attached to testable facts.
Debugging
What Usually Goes Wrong

Most Raster Bugs Are Mismatched Conventions

Coordinates

Flipped origin, missing half-pixel offset, row-column swap, or resampling with the wrong support.

Value Space

Linear-light computation performed on encoded values, or encoded storage interpreted as physical intensity.

Finite Storage

Unintended clipping, too few quantization levels, or silent conversion from float to integer.

Alpha

Straight and premultiplied color mixed together, or transparent pixels carrying hidden colors into filtered edges.

This checklist converts the lecture into debugging advice. When an image is wrong, resist guessing from the final appearance alone. Walk the pipeline and ask where conventions changed: coordinates at sampling, value space during computation, finite format during encoding, channel meaning during storage, and transfer curve during display.
