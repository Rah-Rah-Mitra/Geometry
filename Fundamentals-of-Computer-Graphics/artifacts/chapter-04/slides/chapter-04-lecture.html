Algorithm Skeleton

The Renderer Has Three Large Verbs

1. Generate

Map a pixel center to a viewing ray with origin, direction, and interval.

2. Intersect

Find the closest valid surface hit and return a structured record.

3. Shade

Use hit geometry, lights, material data, and optional secondary rays.

Generate, intersect, shadeThe interval travels with the query
Use the diagram as a control-flow map for the chapter. Ray generation, intersection, and shading are not independent black boxes; the interval chosen for a ray affects the closest hit, the hit record supplies shading data, and the shader may launch more rays with new intervals.
Rendering Organization

Image Order Asks A Pixel Question

Why Ray Tracing First?

The core geometric query can be implemented with vectors, roots, and intervals before building a full raster pipeline.

Natural Effects

Visibility toward a light and visibility in a mirror direction are the same kind of question as camera visibility.

Cost Reminder

A simple ray tracer tests many rays against many surfaces unless later data structures reduce the work.

Pixel-first thinkingPerformance improves later with spatial structure
Contrast the two loop nests without making one sound universally superior. Image-order rendering asks what each pixel sees, which makes shadows and mirror queries natural. Object-order rendering asks where each object lands on the image, which becomes central later in the pipeline chapters.
Ray Generation

Perspective Starts With A Camera Frame

\( \mathbf{d}_{ij} = -d\,\mathbf{w} + u_{ij}\mathbf{u} + v_{ij}\mathbf{v} \)

Camera Contract

  • \(\mathbf{u}\) points right in the image.
  • \(\mathbf{v}\) points upward in the image.
  • \(\mathbf{w}\) points backward from the view direction.

Perspective Rule

All primary rays start at the eye; only their directions change across the raster.

Perspective is implicit in the ray fanNo projection matrix is required for primary rays
Slow down on the camera basis because many ray-tracing bugs begin here. The eye point is not enough; students need the rightward, upward, and backward directions to be orthonormal and consistently oriented. Once that frame is trusted, pixel coordinates become points on a view window.
Sampling Convention

Pixel Centers Become Window Coordinates

\( u_{ij}=l+(r-l)\frac{i+0.5}{n_x} \qquad v_{ij}=b+(t-b)\frac{j+0.5}{n_y} \)

Common Off-By-Half Bug

Sampling pixel corners instead of centers shifts the ray lattice and makes symmetric tests fail subtly.

Inspection Target

The center column should align with the camera view direction when the window is symmetric.

Pixel centers define ray directionsThe half-pixel term is a geometry decision
The half-pixel offset is small enough to look harmless and important enough to shift every sample. Ask learners to compare the blue center samples with the amber corner samples. The equation is less about algebra than about committing to a precise sampling convention before any ray is traced.
Ray Representation

A Ray Carries An Active Interval

Stored Ray Data

  • Origin point \(\mathbf{e}\)
  • Direction vector \(\mathbf{d}\)
  • Current interval \([t_0,t_1]\)

Interpretation

\(t<0\) is behind the eye; \(t\) near zero is dangerous for rays spawned on a surface.

Intervals are part of visibilityThe same parameter orders hit depth
Treat the interval as part of the ray query, not as an afterthought. Negative parameters are behind the eye, very small positive parameters can be numerical self-hits, and the upper endpoint changes when we already know a nearer surface. This convention will unify primary, shadow, and reflection rays.
Ray-Object Intersection

Sphere Intersections Are Quadratic Tests

\( (\mathbf{e}+t\mathbf{d}-\mathbf{c})\cdot(\mathbf{e}+t\mathbf{d}-\mathbf{c})-R^2=0 \)
\(\Delta<0\)miss: no real crossing
\(\Delta=0\)tangent: one grazing root
\(\Delta>0\)enter and exit roots
intervalchoose the first valid root
Implicit surface plus parametric rayRoot order matters
Present the sphere case as the cleanest example of substituting a parametric ray into an implicit surface. The discriminant tells the geometry before any square root is interpreted. Then the interval test decides which root, if any, is visible to the current ray query.
Ray-Triangle Intersection

Triangle Hits Need Barycentric Discipline

\( \mathbf{e}+t\mathbf{d}=\mathbf{a}+\beta(\mathbf{b}-\mathbf{a})+\gamma(\mathbf{c}-\mathbf{a}) \)

Accept The Hit Only If

\(t\in[t_0,t_1]\), \(\beta\ge 0\), \(\gamma\ge 0\), and \(\beta+\gamma\le 1\).

Diagnostic

A correct plane solve can still be a miss when the barycentric point lands outside the triangle.

Plane intersection is necessary but insufficientBarycentric coordinates certify the filled triangle
A plane hit is not automatically a triangle hit. The barycentric coordinates are the bookkeeping that decide whether the ray crosses the filled triangle or only its supporting plane. Emphasize that the same solve returns depth along the ray and coordinates on the surface.
Software Design

Hit Records Are The Interface Boundary

Surface.hit(ray, t0, t1) -> HitRecord HitRecord: t depth along ray x point ray.evaluate(t) n unit surface normal material shading response surface identity for debugging

Why A Record?

Shading, shadows, reflection, and diagnostics all need more than a boolean intersection answer.

Surface classes share one contractThe hit record is the bridge to shading
Use this slide to move from equations into software architecture. Surfaces should not just answer yes or no; they should return the parameter, point data, normal, material reference, and surface identity needed by later stages. That interface makes spheres, triangles, groups, and acceleration structures interchangeable.
Groups Of Objects

Closest Hit Shrinks The Search

closest = miss for surface in group: rec = surface.hit(ray, t0, t1) if rec exists: closest = rec t1 = rec.t return closest

Invariant

The chosen surface must be independent of object-list order.

The group is itself a surfaceSmaller t means more visible
The active interval becomes a correctness device in a group intersection. Whenever a nearer hit is found, later tests are only allowed to report something closer. That rule prevents a far object from overwriting the visible surface and also avoids wasting work on intersections that cannot matter.
Shading Inputs

Shading Begins With Four Vectors

At The Winning Hit

  • \(\mathbf{x}\): point on the surface
  • \(\mathbf{n}\): unit normal
  • \(\mathbf{l}\): direction toward the light
  • \(\mathbf{v}\): direction back toward the viewer
\( \mathbf{x} = \mathbf{e}+t\mathbf{d}, \qquad \mathbf{v} = -\mathbf{d}/\|\mathbf{d}\| \)
Intersection produces shading geometryNormalize before taking dot products
After intersection, shading is no longer mysterious illumination; it is geometry at one point. The point, normal, light direction, and view direction determine the inputs to the material rule. Make students check normalization here, because nonunit vectors silently corrupt dot products and highlight widths.
Extensible Shading

Lights And Materials Split Responsibilities

Light Object

Provides direction, distance, radiance, and optional visibility testing.

Material Object

Evaluates how the surface responds to \(\mathbf{l}\), \(\mathbf{v}\), and \(\mathbf{n}\).

\( C = \sum_{\text{lights}} \text{visible}\cdot E_{\ell}\, f_{\text{material}}(\mathbf{l},\mathbf{v},\mathbf{n}) \)
Architecture prepares for later chaptersAmbient, point, and directional lights fit one loop
Explain the design choice as a way to keep the renderer extensible. A light knows where illumination comes from and a material knows how the surface responds to directions. Adding contributions across lights is simple, but the split keeps future area lights, textures, and better reflectance models from tangling the whole shader.
Shadows

Shadow Rays Ask A Visibility Question

Shadow query: \( \operatorname{scene.hit}(\operatorname{Ray}(\mathbf{x},\mathbf{l}),\,\epsilon,\,r) \)

Why Start At Epsilon?

Starting exactly at the hit point can report the same surface again because floating-point arithmetic is finite.

Point Light Segment

The upper interval endpoint is the light distance, not infinity.

One shadow ray per non-ambient lightVisibility gates illumination
A shadow ray is just another intersection query with a carefully chosen segment. The lower bound is positive so the ray does not immediately rediscover the surface it starts from, and the upper bound reaches the light only for point lights. The result is a binary visibility gate for that light contribution.
Recursive Rays

Mirror Reflection Reuses The Same Query

\( \mathbf{r}=\mathbf{d}-2(\mathbf{d}\cdot\mathbf{n})\mathbf{n} \)

Recursive Contribution

Add a mirror-weighted color from \(\operatorname{shade}(\operatorname{Ray}(\mathbf{x},\mathbf{r}),\epsilon,\infty)\).

Termination Rule

Stop when depth reaches zero or the mirror coefficient is zero.

Reflection is a new ray directionDepth controls infinite bounces
Mirror reflection is powerful because it adds no new intersection machinery. Reflect the incoming direction about the normal, launch a secondary ray with an epsilon start, and multiply the returned color by a mirror coefficient. The depth counter is the explicit engineering guard against infinite bouncing.
Debugging And Checks

Numerical Guardrails Keep The Picture Honest

Camera Frame

Check orthonormality and verify that the center ray points in the intended view direction.

Intersections

Sort sphere roots, enforce intervals, and reject triangle plane hits outside the barycentric simplex.

Secondary Rays

Use a scene-scale epsilon and finite light segment to avoid self-hit artifacts.

Notebook checks target implementation hazardsTrust comes from invariants, not only pictures

Chapter Summary

Takeaways: Ray Tracing Is Simple To State, Exacting To Implement

Core Idea

Perspective appears because rays fan out from the eye through the image window.

Implementation Idea

Every surface answers the same interval-aware hit query and returns the data shading needs.

Reliability Idea

Secondary rays need epsilon offsets and depth limits, because numerical geometry is part of the algorithm.

Next: surface shading models use the same vectors more richlyRay tracing remains a reusable visibility primitive
Close by naming the transferable ideas. Ray tracing is easy to state because the outer loop is just over pixels, but reliable implementations depend on exact camera sampling, interval-aware intersections, rich hit records, and secondary rays with numerical offsets and termination rules.
