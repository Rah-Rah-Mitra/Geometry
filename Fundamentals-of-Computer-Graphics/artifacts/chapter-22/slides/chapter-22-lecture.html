Fundamentals of Computer Graphics - Chapter 22

Computer Graphics in Games

Budgets, latency, platforms, optimization, game type, and production workflow as one renderer design problem.

Source span: printed pages 623-644; PDF pages 640-661.

Open the lecture by treating game graphics as applied resource economics. A game renderer is not merely selecting algorithms; it is allocating frame time, memory, bandwidth, tool effort, and schedule risk while preserving playability. The chapter span gives us a compact tour from platform choice to production workflow.
Core Lens

Renderer Decisions Are Budget Transfers

Decision Test

Name the resource saved, the resource spent, and the bottleneck that actually moves.

Examples
  • Normal maps save geometry but spend texture memory and bandwidth.
  • Depth prepasses save pixel work but submit geometry twice.
  • Streaming saves memory but spends I/O scheduling and tool discipline.
Warning

An optimization that does not touch the limiting pool may be invisible to the frame rate.

Use the budget exchange as the recurring diagnostic. Every graphics decision should name what it spends and what it saves. If a technique saves triangles but the missed budget is texture bandwidth, the frame may not improve. This framing keeps platforms, optimization, genre, and tools connected.
22.1 Platforms

A Platform Is A Resource Envelope

Fixed Console

Predictable hardware and timing, stricter memory accounting, lower API abstraction, and certification pressure.

Variable PC

Broad customer reach and high ceilings, but the renderer must scale across unknown present and future machines.

Browser Or VM

Stable deployment and high abstraction, with lower native access and modest graphics expectations.

Handheld Mobile

Capable hardware constrained by thermal behavior, power, memory pressure, bandwidth, and input form.

Emphasize that a platform is a contract, not a brand label. The renderer inherits variance, API abstraction, input devices, certification rules, and resource ceilings. The same technique can be wise on a fixed console, risky on a browser target, and essential on a highly variable PC audience.
Platform Variance

Quality Knobs Make One Game Fit Many Machines

Scales Well
  • Display resolution and upscaling
  • Antialiasing sample count
  • Shadow map resolution or cascade count
  • Optional post effects and texture tier
Design Constraint

Knobs must preserve gameplay readability, not just increase benchmark numbers.

Course Artifact Check

486 synthetic settings were swept; the chosen 60 fps setting fit both frame and memory budgets.

Quality scaling belongs early because it is a design obligation on variable platforms. Resolution and antialiasing are simple user-facing knobs, while shadows, post effects, and texture tiers often require deeper pipeline support. The key is to scale visual cost without breaking game readability.
22.2 Limited Resources

Frame Rate Converts Graphics Into Deadlines

Frame Arithmetic

\( t_{\mathrm{frame}} = 1000 / \mathrm{fps} \)

33.3 ms 30 fps frame budget
16.7 ms 60 fps frame budget
Parallel Work

Input, simulation, animation, audio, networking, CPU submission, and GPU execution overlap but still meet one displayed frame deadline.

Frame time turns responsiveness into arithmetic. A 30 fps target gives about 33.3 milliseconds, while 60 fps gives about 16.7 milliseconds for input, simulation, submission, and display work. Because many tasks overlap, the slowest active lane determines whether the frame deadline is missed.
Processing Time

Command Buffers Trade Starvation Against Latency

Benefit

A full queue prevents GPU starvation when CPU submission timing varies.

Cost

Commands generated from old input may appear one or more refreshes later.

Fast Games

Latency-sensitive genres often prefer tighter queues and 60 fps targets.

A command buffer is useful because it keeps the GPU fed, but it also moves player input farther from the displayed image. Fast games often sacrifice some throughput convenience to reduce latency. The right buffer depth depends on how painful starvation is compared with delayed feedback.
Heterogeneous Resources

The Bottleneck Lane Controls Frame Time

Synthetic Chapter Check

\( t_{\mathrm{frame}} = \max(t_{\mathrm{CPU}}, t_{\mathrm{vertex}}, t_{\mathrm{pixel}}, t_{\mathrm{texture}}, t_{\mathrm{bandwidth}}) \)

Observed Limit

Baseline frame time: 21.6 ms. The limiting pool is GPU programmable work, so a 60 fps target misses until that lane is reduced.

Useful Question

Which lane has the longest bar after synchronization and queueing are accounted for?

Heterogeneous GPU resources explain why profiling must precede optimization. Pixel shading, texture fetch, bandwidth, and post processing can each become the limiting lane. Reducing a non-bottleneck lane may clean up code, but it does not change frame time until the bottleneck lane moves.
Storage, Latency, And Bandwidth

Memory Budgets Are Hierarchies, Not Buckets

Graphics Memory Pressure

Textures usually dominate, followed by geometry, animation data, buffers, and supporting game systems.

Mip Arithmetic

\(1 + 1/4 + 1/16 + \cdots \approx 4/3\)

A 2048 RGBA base level is 16.0 MiB; the full mip chain in the artifact is about 1.333 times larger.

Latency Hiding

Shader math can cover some texture wait time, but only when there is enough independent work.

Storage constraints are more than capacity limits. The hierarchy trades size against latency and bandwidth, so loading, streaming, texture access, and cache behavior shape graphics design. Games often spend engineering effort to stage assets near the processor that will consume them.
Development Resources

A Runtime Feature Must Be Authorable

Limited Team Time

The cost of a technique includes programmers, tools engineers, technical artists, content artists, QA, and iteration time.

Artist Productivity

Most modern game visuals are asset heavy. Preview speed and failure clarity can determine final image quality.

Practical Rule

If the team cannot create and revise inputs reliably, the shader or renderer feature is not production ready.

Development resources are a first-class constraint. A shader feature that requires fragile tools, slow previews, or repeated artist handoffs may be more expensive than its runtime cost suggests. A production renderer succeeds only when artists can create, inspect, revise, and validate assets efficiently.
22.3 Optimization Techniques

Reject Invisible Pixels Before They Run Expensive Shaders

Depth Culling

Hierarchical depth hardware can skip pixel shaders on surfaces already known to be hidden.

Depth Prepass

Render opaque depth first without expensive color shading, then shade with stronger rejection.

Tradeoff

The method pays extra vertex and draw work, so it helps most when pixel work dominates.

Depth and visibility optimizations should be presented as early rejection mechanisms. If an expensive pixel shader never runs, the engine saves time without changing the visible image. A prepass spends simpler geometry work up front, so the value depends on whether pixel work is truly costly.
Visibility And Level Of Detail

The Fastest Object Is Not Submitted

520 objects in synthetic scene
227 frustum survivors
207 after occlusion culling
0.406M triangles after LOD
LOD Contract

Reduce detail with distance or screen coverage while keeping silhouettes and material behavior stable.

Culling and level of detail are complementary. Frustum and occlusion culling remove objects from consideration, while LOD keeps visible objects but changes their representation. The numeric reduction is useful, but the visual contract is stricter: silhouettes, materials, and switching behavior must stay believable.
Precompute When The World Allows It

Static Backgrounds Can Store Expensive Lighting

Background Geometry

Static scenery can use precomputed lighting stored as lightmaps or related data.

Foreground Geometry

Characters and moving objects need dynamic shading, lighting probes, or other position-aware approximations.

Genre Dependency

Changing time of day and open worlds reduce how much lighting can be baked in advance.

Precomputed lighting is a classic game graphics bargain. It moves expensive global illumination out of the frame, but it favors static background geometry and fixed lighting assumptions. Dynamic characters and changing worlds need probes, approximations, or runtime shading because they cannot simply reuse one baked map.
22.4 Game Types

Genre Predicts Camera, Content, And Latency Pressure

Small, Enclosed World

Spend more on local fidelity, fixed camera composition, and highly detailed hero objects.

Large Or Free World

Prioritize streaming, culling, LOD, memory residency, and lighting that tolerates change.

Latency Sensitive

Rhythm, fighting, and shooter experiences often spend visual budget to maintain faster feedback.

Genre changes the renderer because it changes what can be seen and how quickly the player notices delay. A fighting arena can spend detail on a tiny world. An open-world game must stream and cull. A strategy game budgets for many actors rather than two hero characters.
22.5 Asset Creation

Asset Pipelines Turn Graphics Ideas Into Dependencies

Topology Of Work

Modeling, UVs, detail sculpting, normal baking, shader assignment, lighting, import, and profiling form an acyclic dependency graph.

Late Changes

Changing a mesh can invalidate UVs, baked maps, shader bindings, rig weights, animations, and QA evidence.

Chapter Artifact

The generated workflow check found 24 nodes, 27 edges, and a 12-edge critical path.

The asset pipeline slide links runtime choices to authoring dependencies. Normal maps, shader parameters, lightmaps, rigs, and animations are not isolated files; they form a directed workflow. A late upstream change can invalidate many downstream approvals, so the graph is also a schedule model.
Game Production Process

Graphics Work Changes Shape Across Production

Pre-Production

Core team prepares engine changes, tools, rendering experiments, and gameplay prototypes before the full team depends on them.

Full Production

Assets, levels, animation, lighting, effects, and engine refinements iterate together under schedule pressure.

Final Stage

Alpha, beta, gold, patches, and DLC shift attention from exploration to stability, performance, QA, and certification.

The production timeline explains why pre-production tools matter. If the core team does not prepare the engine and pipeline before full production, many specialists can become blocked. Alpha, beta, and gold are not just labels; each stage changes the kind of graphics work that is still affordable.
Synthesis

Profile, Then Choose The Smallest Quality Concession

Target Chosen Frame Memory Key Settings
30 fps 16.983 ms 1605 MB 4x AA, medium textures
60 fps 15.207 ms 1055 MB 2x AA, low textures
Procedure
  1. Measure frame, memory, bandwidth, latency, and quality.
  2. Identify the missed constraint and the current bottleneck.
  3. Adjust the cheapest visible knob that moves that constraint.
  4. Verify on the target platform and game type.

The chapter's practical habit: make the hidden tradeoff explicit, then verify that the measured bottleneck actually changed.

Close by asking students to defend an optimization as a measured tradeoff. The best quality setting is not the prettiest candidate in isolation; it is the highest-quality candidate that fits frame, memory, bandwidth, latency, and production constraints on the target platform and game type.
