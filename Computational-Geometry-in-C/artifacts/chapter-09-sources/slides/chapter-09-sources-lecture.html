Three Practical Entry Points

Handbook surveys

Big-picture orientation. Read a survey chapter when you want to learn the shape of a subfield and its named subtopics before diving into a single result.

Best when: you do not yet know what to search for.

Community bibliography

Paper-level discovery. Once you know which subtopic interests you, a curated bibliography hands you the cluster of relevant papers and citations.

Best when: you have a focused question and need related work.

Software directory

Executable tooling. A directory routes you to libraries that already implement convex hulls, Delaunay triangulations, predicates, and visibility queries with documented numerical conventions.

Best when: you need to compute, not just cite.

Three orthogonal axes: orient, discover, executeMost reading sessions touch at least two of the three

Recurring Warning

Exact arithmetic does not eliminate degeneracy. Orientation tests, collinearity rules, and tie-breaking conventions remain user decisions.

Capability and caution travel togetherPredicate layer is where most surprises live
Slow down on software. A robust hull or Voronoi package, a geometry class library, and reference code from textbooks each solve different things. Library abstractions must match the predicates used in the proof. Even an exact-arithmetic backend does not absolve the user from understanding degeneracy conventions, orientation tests, and numeric ranges.

Three-Source Reading Path Lab

Recipe

Pick one algorithm family. Build a three-step reading path: textbook for definitions, survey for variants, software docs for degeneracy.

Worked Example: Voronoi diagrams

1. Textbook account of Voronoi and Delaunay duality.
2. Handbook survey for weighted, power, and higher-order variants.
3. Library docs for in-circle predicate, degeneracy, and tie-breaking.

Worked Example: Arrangements

1. Monograph for arrangement complexity and zone theorems.
2. Survey for applications (hidden-surface removal, ham-sandwich).
3. Library docs for line and segment arrangement primitives.

The lab is about choosing sources, not memorizing themRepeat for the algorithm family you care about
Walk through the applied lab. Pick one algorithm family, then build a three-step reading path: a textbook account for definitions and core proofs, a handbook or survey for variants and applications, and a software documentation page for degeneracy and precision conventions. Use Voronoi diagrams or arrangements as the worked example; both have all three layers.

Sources as a Toolkit, Not a Directory

Closing Claim

The field is too broad and too active to be captured by one book. Use the typology to keep learning.

  • Discovery: bibliographies and FAQs.
  • Coherent explanations: textbooks and collections.
  • Depth: monographs.
  • Frontier: journals and conferences.
  • Executable machinery: software, with predicate awareness.
