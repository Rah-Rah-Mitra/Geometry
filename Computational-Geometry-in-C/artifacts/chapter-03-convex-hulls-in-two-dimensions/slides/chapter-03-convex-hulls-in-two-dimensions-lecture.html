Why Hulls Matter: Envelopes, Strips, Boxes, Outlines

Boundary As Summary

Many downstream measurements depend only on extreme points: diameter, width, enclosing rectangles, and collision envelopes.

Algorithmic Payoff

If the hull has \(h\) vertices and \(h \ll n\), output-sensitive algorithms can exploit the small final boundary.

Careful Distinction

The hull is not every point in the data set. Interior points may be important data, but they are irrelevant to the convex boundary.

Applications read geometry from supporting directionsMost computations start by filtering nonextreme points
Motivate the hull as a reusable geometric compression. A robot arm envelope, a thin containing strip, a minimum box, and a visible shape outline are different questions, but they all ask which input points support the outside. This gives a practical reason to care about extreme points before any algorithm appears.
Convex Sets
segment test and half-planes

What Convex Means: Segments And Half-Plane Intersections

Definition

A set \(S\) is convex when every segment \(\overline{ab}\) with \(a,b \in S\) stays inside \(S\).

Combination View

\((1-\lambda)a+\lambda b \in S,\quad 0 \le \lambda \le 1.\)

Half-Plane View

An intersection of half-planes is convex, so a polygon bounded by supporting lines gives a clean model for hull geometry.

Convexity is local along every chordHull algorithms repeatedly discover supporting half-planes
Give both equivalent mental models. The segment test is the direct definition students can inspect visually, while the half-plane intersection model explains why boundary edges have supporting lines. Convex hull algorithms keep asking which line, edge, or direction exposes the next piece of that boundary.
Hull Output

Hull Boundary And Extreme Points

Extreme Point

A point of \(P\) is extreme when it is a vertex of \(\mathrm{conv}(P)\), equivalently not expressible as a strict convex combination of other points of the hull region.

Boundary Output

Most implementations return extreme vertices cyclically, not a filled set of all points in the polygon.

Ordering Matters

The same set of extreme points is not yet a usable polygon until adjacent vertices are in clockwise or counterclockwise order.

Extreme point set + cyclic order = polygon boundaryNonextreme points can be certified and discarded
Pause on output format, because it prevents later confusion. The filled hull is a continuum of points, but the algorithm returns a cyclic vertex list. The hard part is not merely naming which points are extreme; students also need to understand why the order of those points is part of the certificate.
Primitive Predicate
one determinant drives the chapter

The Predicate Under Everything: Orientation Determinant

Orientation

\(\operatorname{orient}(a,b,c)= (b_x-a_x)(c_y-a_y)-(b_y-a_y)(c_x-a_x)\)

Sign Meaning

  • \(>0\): \(a \to b \to c\) makes a left turn.
  • \(<0\): it makes a right turn.
  • \(=0\): the three points are collinear.

Algorithmic Role

Every edge test, tangent walk, and Graham stack pop is a question about this sign.

Predicate first, data structure secondRobustness later means preserving this sign reliably
Make the determinant feel like the chapter's vocabulary. It is twice a signed triangle area, so its sign tells us whether the third point lies left, right, or on the directed line. From here onward, every algorithmic decision can be translated into a repeated orientation question.
Slow Certificate

Naive Nonextreme Test With Witness Triangle

Witness Principle

If \(p\) lies inside a triangle whose vertices are other input points, then \(p\) cannot be an extreme point of the full set.

Why It Works

A triangle is convex. Once \(p\) is inside that triangle, it is also inside the convex hull of all input points.

Why It Is Slow

Trying many triples makes the test useful for definitions and debugging, not as the final production algorithm.

Check: every_marked_point_has_witness_triangle = trueSlow tests clarify what later algorithms avoid doing
Use the notebook visual as a certificate, not as decoration. A nonextreme point is proved nonextreme by a specific triangle of other points that contains it. This deliberately slow idea helps students see what is being discarded before the lecture moves to edge-based and output-sensitive methods.
From Edges To Algorithm
all points on one side

Extreme Edges To Gift Wrapping

Extreme Edge Test

A directed edge \(ab\) is a hull edge when every other input point lies on the same side of the line through \(a\) and \(b\), allowing collinear boundary cases by convention.

Gift Wrapping Move

Start at a known extreme point, then choose the next point so every other point is to the same side of the candidate directed edge.

Local To Global

Each accepted edge is locally certified against all points; chaining accepted edges wraps the whole boundary.

Extreme edge test scans all pointsGift wrapping repeats the scan once per hull vertex
Connect the static edge test to Jarvis style wrapping. If a directed candidate edge leaves every point on the permitted side, it belongs to the hull. Gift wrapping does this test repeatedly: from the current vertex, rotate the candidate until no point lies outside the exposed side.
Output Sensitivity
cost depends on h

Gift Wrapping Cost \(O(nh)\)

Runtime

\(h\) accepted edges \( \times \) \(n\) scanned points \(= O(nh)\)

When It Shines

If only a few points lie on the hull, the algorithm can be much cheaper than sorting all \(n\) points.

When It Hurts

If almost every point is extreme, then \(h \approx n\) and the scan becomes quadratic.

Output-sensitive but not uniformly optimalNotebook check: output_sensitive_cost_drops_when_h_is_small
Name the variable h explicitly as the number of output vertices. Gift wrapping pays for one full scan per edge it reports, which is ideal when the boundary is tiny and painful when most points are on the boundary. This slide sets up the search for algorithms with different cost profiles.
Divide And Filter
discard triangles, recurse outside

QuickHull Recursion

Recursive Step

For an exposed segment, find the point farthest from its line. The triangle formed by the segment and that farthest point cannot contain future hull vertices in its interior.

Good Case

Large discard triangles shrink the candidate sets rapidly.

Worst Case

Badly balanced splits can still leave many points for later calls, so QuickHull is heuristic-friendly but not worst-case magic.

Check: quickhull_records_discards = trueSame determinant, different recursion tree
Present QuickHull as a filtering algorithm. It uses a farthest point to create two new candidate edges and a triangle that can be thrown away. The important invariant is that only points outside the exposed triangle can still affect the boundary, while the caution is that the recursion can be badly balanced.

Three Algorithms, One Hull

Gift Wrapping

Walks from one exposed vertex to the next; easy to explain and output-sensitive.

QuickHull

Splits the problem with farthest witnesses and discards triangle interiors.

Graham Scan

Sorts by angle once, then keeps a stack whose turns stay consistent.

Graham Scan I
sort before scanning

Graham Scan Setup

Setup

Choose a pivot, usually the lowest then leftmost point. Sort all other points by polar angle around the pivot, breaking ties by distance in a consistent way.

Why Sort

The angular order gives a simple walk around the outside, so the stack only has to repair local right turns.

Tie Caution

Multiple points on the same ray from the pivot must be handled deliberately or the scan may keep a nearer collinear point on the boundary.

Sorting front-loads the \(n \log n\) workThe scan phase is linear after sorting
Separate Graham scan into a setup phase and a stack phase. The sort by polar angle is the expensive global operation, and it creates a traversal order where local orientation tests are enough. Tie handling belongs in the setup, because collinear rays can otherwise put the wrong point on the stack.
Graham Scan II
checked artifact: stack never keeps a right turn

Graham Stack Invariant

Stack Invariant

After each processed point, the stack is the convex hull of the processed prefix in angular order.

Pop Rule

While the last two stack points and the new point make a forbidden right turn, remove the middle endpoint from the stack.

Why Linear After Sorting

Each point is pushed once and popped at most once, so stack maintenance is \(O(n)\).

Check: stack_never_keeps_right_turn = trueLocal orientation repairs maintain a global hull prefix
Emphasize the invariant rather than the mechanics alone. At any moment the stack is supposed to be the hull of points already encountered in angular order. A right turn exposes a concavity, so the middle stack point cannot remain on the processed-prefix hull and is popped before the new point is accepted.
Implementation Robustness
degeneracy is part of the specification

Implementation Robustness

Collinearity

Decide whether boundary collinear points are reported, skipped, or coalesced into endpoints. The choice must be consistent across edge tests and stack pops.

Duplicate Points

Remove exact duplicates or define a stable comparison so the output boundary is not polluted by zero-length edges.

Numeric Signs

Floating data needs a tolerance policy; integer data can use exact arithmetic until products overflow the chosen type.

Ordering

Every hull consumer should know whether the output is clockwise or counterclockwise and whether the first vertex is canonical.

Warning

A hull algorithm is only as reliable as its orientation sign and degeneracy conventions. The mathematics says what the predicate means; the implementation must preserve that meaning under real input data.

Degenerate cases change boundary representation, not the core definitionsDocument conventions before comparing outputs
This is the engineering checkpoint. The abstract algorithms assume clean inputs, but real inputs contain duplicate points, collinear runs, and nearly zero determinants. The goal is not to pretend these cases vanish; it is to choose conventions and arithmetic that make the output certificate match the intended hull.
Lower Bound
parabola reduction to ordered output

Lower Bound By Parabola

Reduction

Map numbers \(x_i\) to points \((x_i,x_i^2)\). The lower hull lists those points by increasing \(x_i\).

Consequence

If an algorithm outputs hull vertices in sorted boundary order, then it can be used to sort arbitrary numbers.

Barrier

Comparison-based ordered hull output therefore inherits the \(\Omega(n \log n)\) lower bound from sorting.

Check: parabola_hull_order_sorts_inputs = trueThe lower bound is about ordered output, not just membership
Make the reduction concrete. Put each input number on the parabola y equals x squared. Because the curve is strictly convex, the hull chain exposes the points in increasing x order. Therefore an ordered hull routine would sort the numbers, so ordered hull output cannot beat the sorting lower bound in the comparison model.
Beyond Graham

Beyond Graham: Incremental And Divide-And-Conquer

Incremental Hull

Maintain a hull for processed points. When a new outside point arrives, find its tangents and replace the covered chain.

Divide And Conquer

Compute left and right hulls, then merge them by walking upper and lower common tangents.

Extensions

Output-sensitive \(O(n \log h)\) methods, rotating calipers, and onion layers all build on ordered hull boundaries.

Local invariant: maintain supporting tangentsHull boundary order becomes a reusable data structure
Use this slide as a map beyond the three central algorithms. Incremental insertion and divide-and-conquer both depend on tangent certificates, just in different workflows. Once students trust tangent walks on ordered hulls, rotating calipers, onion layers, and output-sensitive improvements become natural continuations rather than unrelated tricks.
