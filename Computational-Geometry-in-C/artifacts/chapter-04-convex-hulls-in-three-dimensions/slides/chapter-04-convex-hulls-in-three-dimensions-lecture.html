Definitions · Surface Validity

What Counts As A Polyhedron

Working Definition

A polyhedron is represented by a finite boundary of planar polygonal faces whose intersections are whole edges, whole vertices, or empty.

Validity Tests

  • Every edge has exactly two incident faces.
  • Local neighborhoods on the surface behave like disks.
  • Face orientations can be made globally consistent.
  • For this chapter, genus zero is the default hull topology.
Implementation lens: invalid incidence can be created accidentally during deletion.Topology comes before predicates.
Slow down on the word polyhedron because implementation bugs often create objects that look plausible but are not valid surfaces. Every edge should have two incident faces, neighborhoods should look locally like disks, and genus zero is the setting where the simple Euler ledger applies.
Invariant · Convex Polytopes

Convex Polytopes And Euler's Ledger

Euler Characteristic

For a convex polyhedron with genus zero, \(V-E+F=2\).

\(8-18+12=2\)
QuantityNotebook ValueUse In Implementation
\(V\)8hull vertices after filtering interior points
\(E\)18unique undirected surface edges
\(F\)12triangular facets from the hull surface
\(V-E+F\)2topological sanity check

Triangulated hulls satisfy \(3F=2E\), so Euler gives linear edge and face counts.

Read the table as both theorem and instrumentation. In a triangulated convex hull, Euler gives V minus E plus F equal to two, and triangular faces force edge and face counts to be linear in the number of hull vertices. The notebook check records V equals eight, E equals eighteen, F equals twelve.
Proof Roadmap

Proof Roadmap For Euler

1. Stretch

Remove one face and flatten the boundary to a connected plane graph.

2. Trees

For a tree, \(E=V-1\) and there is one exterior face, so \(V-E+F=2\).

3. Cycles

Deleting a non-bridge edge lowers both \(E\) and \(F\) by one, preserving the ledger.

Do not reproduce a full proof here; teach the structure. Stretch the polyhedron to a plane graph, verify the tree case, and remove one cycle edge at a time. The invariant survives because deleting a cycle edge reduces both E and F by one.
Algorithmic Shift

Why 3D Hulls Are Harder Than 2D

2D Hull Boundary

  • Maintain a polygonal cycle.
  • Insertion finds two tangents.
  • Local replacement is an interval on the cycle.

3D Hull Boundary

  • Maintain a 2D cell complex.
  • Insertion may delete many faces.
  • Replacement is a cone over horizon edges.
Compare the data maintained by a 2D hull and a 3D hull. In two dimensions the boundary is a cyclic list with tangent edits. In three dimensions a point update deletes a connected patch, finds a horizon cycle, and creates many cone faces while preserving orientation.

Predicate · Oriented Tetrahedron

Signed Volume Predicate

Visibility Test

For oriented face \((a,b,c)\), classify point \(p\) by the sign of

\(6\,\mathrm{Vol}(a,b,c,p)=\det(b-a,\ c-a,\ p-a)\)

Sign Discipline

Visible means the new point lies on the outside side of the oriented face. The exact positive or negative convention depends on orientation, so every face must agree.

Tie the formula to the 2D orientation test students already know. The determinant is six times the oriented tetrahedron volume, so an oriented face can classify a new point by sign. The sign convention depends on face orientation; consistency matters more than the particular choice.

Implementation Records

Vertex, Edge, Face Records And Flags

Edgeendpoints, adjacent faceshorizon, new, delete

Why Flags?

Visibility, horizon detection, and cleanup are coupled. Mark first, traverse while references still exist, then remove deleted records in a controlled pass.

Make the record fields concrete without copying C code. Vertices, edges, and faces carry flags so the update can mark visible faces, horizon edges, and deletion candidates before physically removing anything. This delayed cleanup is what keeps traversal from invalidating itself mid-walk.
Implementation Audit

Orientation And Cleanup

Orient

Each new cone face must point consistently with the surviving hull surface.

Delete

Visible faces are removed after horizon edges and new cone faces are recorded.

Purge

Edges and vertices unsupported by remaining faces should not survive as stale records.

Checks: Euler characteristic, orientation signs, horizon count.Different checks catch different failures.
Use this as an implementation checklist. New cone faces must be oriented consistently with the surviving surface, old visible faces must be deleted, and edges or vertices with no remaining support should be cleaned. Euler and orientation checks catch different classes of mistakes.
Robustness

Degeneracy And Robustness

Failure Modes

  • Four or more points can be coplanar.
  • A new point can lie nearly on an existing face.
  • Duplicate or interior points should not create surface records.
  • Integer determinants can overflow under large coordinates.

Symbolic

Declare a deterministic perturbation or tie-breaking rule.

Exact

Use arithmetic that preserves determinant signs when inputs are integral.

Filtered

Compute fast approximate signs, then certify near-zero cases.

Stress that the clean determinant story assumes general position. Coplanar or nearly coplanar points, repeated points, and large integer coordinates can make signs ambiguous or overflow. Connect this directly to the notebook lab: moving a point close to a face should make students ask whether the sign is certified, perturbed, or treated as coplanar. Robust implementations need an explicit policy, not hope.

Check

The conflict graph is bipartite: outside points on one side, hull faces on the other.

Explain conflicts as cached visibility. Instead of scanning every face for every outside point, the algorithm records which outside points can see which faces. When visible faces are deleted, only conflicts attached to the affected neighborhood need to be redistributed.
Beyond 3D

Higher Dimensions And Output Sensitivity

3D Comfort

Euler ties \(V\), \(E\), and \(F\) linearly for triangulated genus-zero hulls.

Higher-D Warning

Facet counts can grow much faster than the number of vertices.

Output Sensitivity

Runtime statements must mention output size, because writing all faces may dominate the computation.

Notebook proxy: cyclic-style growth outpaces the 3D linear proxy.Check: cyclic_style_growth_exceeds_simplex_growth.
Use the growth plot to separate algorithmic overhead from output size. In three dimensions Euler keeps the hull surface linear in the number of vertices, but higher-dimensional polytopes can have many more faces. The output can be the bottleneck before implementation details enter.
