The Planning Problem

Configuration

A point \(q \in C\) records all parameters needed to place the robot: position, angle, or joint angles.

Free Space

\(C_{\mathrm{free}} = C \setminus C_{\mathrm{obs}}\)

Collisions define \(C_{\mathrm{obs}}\); feasible motions are continuous curves in \(C_{\mathrm{free}}\).

Common Pitfall

Searching the drawing of the room is not enough once the robot has radius, shape, rotation, or articulated joints.

Problem data: robot, obstacles, start, targetOutput: a continuous collision-free motion or a certificate of no path
Set up the vocabulary before any algorithm appears. A configuration is one complete placement of the robot, obstacles carve out forbidden configurations, and a feasible motion is a continuous curve that stays in free space. The drawing deliberately separates workspace intuition from configuration-space bookkeeping.

Point Robot: Infinite Paths To Finite Graph

Visibility Principle

A shortest path among polygonal obstacles is polygonal, and every interior turn can be placed at an obstacle vertex.

Notebook Witness

The checked path uses only visibility edges: \(s \to O0.1 \to O1.1 \to t\).

Algorithmic Translation

Build visible edges between start, target, and obstacle vertices; weight edges by Euclidean length; run Dijkstra.

Artifact: figures/visibility-graph-shortest-path.pngCheck: shortest_path_uses_visible_edges = true
Use the notebook visual as the first concrete reduction. Infinitely many polygonal routes are possible, but a shortest route only needs to turn at obstacle vertices. Once those visible vertex pairs are turned into graph edges, the geometric problem becomes a weighted graph problem with fourteen nodes and twenty-seven visibility edges in the checked scene.
Proof Roadmap
straighten until a vertex blocks

Visibility Lemma Proof Roadmap

Proof Moves
  1. Replace any curved subpath in free space by the straight segment if visible.
  2. If a bend is not forced by an obstacle vertex, perturb it to shorten the route.
  3. Repeat until all turns are start, target, or obstacle vertices.

What The Lemma Does Not Say

It does not make all visibility edges part of the answer; it only says the optimum is contained in the graph search space.

Reduction: continuum of paths -> finite candidate turnsThe graph is a superset of shortest-path possibilities
The proof idea should feel physical. If a shortest path bends in empty space, slide or pull the bend until it either disappears or hits an obstacle vertex. Repeating this local straightening leaves only start, target, and obstacle vertices as possible turn points. That is the bridge from continuous paths to a finite graph.

Dijkstra As Paint Spread

Invariant

When a vertex is settled, the shortest route to it is known; no later frontier can beat that distance.

Notebook Path

Settled route: \(s\), \(O0.1\), \(O1.1\), \(t\). The direct segment is blocked, so graph weights carry the detour.

Paint intuition: start at \(s\), expand distance uniformly along visible edges, and freeze each vertex the first time the front reaches it.

Graph edges are geometric visibility segmentsDijkstra supplies the finite optimization step
Explain Dijkstra with the paint-spread picture because it matches shortest-path geometry. Distances expand from the start like a front. The next settled vertex is the first unsettled vertex reached by the front, so its distance can no longer improve. In the notebook scene, the settled chain recovers s, O0.1, O1.1, and t.

Disk Robot: Grow The Obstacles

Center Reduction

The disk is collision-free exactly when its center avoids the obstacle offset by radius \(r\).

Checked Conditions

Expanded obstacles are larger, and both start and goal centers remain outside the expanded forbidden regions.

Boundary Meaning

A center on the offset boundary means the disk is tangent to an obstacle, so path conventions must specify whether contact is allowed.

Artifact: figures/disk-robot-expanded-obstacles.pngCheck: start_and_goal_outside_expanded_obstacles = true
Now change the robot, not the algorithm. A disk collides when its center gets within one radius of an obstacle, so the disk center must avoid expanded obstacles. This converts the disk robot back into a point robot problem, provided the start and target centers remain outside the grown forbidden regions.
Configuration Obstacles
reflection makes collision algebraic

Minkowski Sum Language

Minkowski Sum

\(A+B=\{a+b : a\in A,\; b\in B\}\)

Collision Test

A translating robot \(R\) with reference point \(q\) collides with obstacle \(P\) exactly when \(q \in P + (-R)\).

For a disk, \(P + (-R)\) is simply the radius-expanded obstacle. For a polygon robot, the same idea creates polygonal configuration obstacles.

Algebraic growth replaces contact reasoningThe reference point is now a point robot in \(C\)-space
Introduce Minkowski addition as the notation that makes obstacle growth precise. The forbidden reference-point region is the obstacle plus the reflected robot. Reflection matters because we ask where the robot's reference point can be placed so that some robot point overlaps an obstacle point.
Convex Translation
15 sums -> 8 hull vertices

Convex Polygon Translation

Computation
  1. Reflect the robot around its reference point.
  2. Add every obstacle vertex to every reflected robot vertex.
  3. Take the convex hull of those sums.

Notebook Witness

Obstacle vertices: 5. Robot vertices: 3. Pairwise sum points: 15. Minkowski hull vertices: 8.

Geometric Meaning

The hull is not a decorative enlargement; it is exactly the forbidden region for the robot reference point in this convex translation model.

Artifact: figures/convex-robot-minkowski-sum.pngCheck: minkowski_sum_has_convex_hull = true
Use the convex robot artifact to make the formula computational. The notebook forms all pairwise sums between obstacle vertices and reflected robot vertices, then takes the convex hull. In the checked example, fifteen pairwise sums collapse to an eight-vertex convex configuration-space obstacle.

From Translation To Free-Space Components

Decision Version

Are \(q_s\) and \(q_t\) in the same connected component of \(C_{\mathrm{free}}\)?

Roadmap Role

Replace each free component by a finite graph spine; graph connectivity answers the decision question.

Path Role

Once a graph route exists, expand it back into a continuous motion inside the cells or corridors represented by the graph.

Obstacle growth is only step onePlanning asks how \(C_{\mathrm{free}}\) is connected
Tie the growth construction to the decision problem. Once every obstacle is replaced by a configuration-space obstacle, the question is whether the start and target reference points occupy the same connected component of free space. A path planner can then search a roadmap, a cell graph, or another finite representation.
More Degrees Of Freedom
translation plus angle

Ladder: Rotation Adds A Dimension

Ladder Configuration

A segment of fixed length needs a reference point \((x,y)\) and an orientation angle \(\theta\).

Why This Matters

A path that is impossible in one angle slice can become possible by changing angle while translating.

The chapter uses the ladder as a gateway from two-dimensional floor plans to higher-dimensional configuration spaces.

For a ladder, \(C\) has coordinates \((x,y,\theta)\)Rotation changes the connectedness of feasible motion
The ladder is the warning that translation-only pictures are not enough. A rigid segment has position and angle, so the configuration space has one more dimension than the floor plan. Narrow passages can be reachable only by coordinating translation with rotation, which is why the slide uses slices by angle.

Cell Decomposition And Retraction

Planner Recipe
  1. Partition \(C_{\mathrm{free}}\) into simple cells.
  2. Connect adjacent cells in a graph.
  3. Retract motion inside cells to a graph route.

Why Retraction Helps

It preserves component connectivity while replacing an infinite set of positions by vertices and edges.

Course Theme

This is the same reduction rhythm as visibility graphs: prove the finite structure is rich enough, then search it.

Cell graph answers decision and path questionsShortest path may need extra metric structure
Present cell decomposition as the general recipe behind many planners. Decompose free space into simple cells, connect adjacent cells in a graph, and retract each cell to a lower-dimensional spine. The important idea is not the exact decomposition shown, but the reduction from continuous motion to graph connectivity.

Constructive Arm Proof

Two-Kinks Construction

Two-Kinks Theorem

If a target is reachable by a polygonal arm, then there is a reaching configuration with at most two nonzero changes of direction.

Construction
  1. Split links into two groups of total lengths \(a\) and \(b\).
  2. Intersect the circle of radius \(a\) around the base with the circle of radius \(b\) around the target.
  3. Lay each group straight along its solved direction.
Grouped lengths: 2.6 and 1.5Check: arm_endpoint_hits_target = true
The two-kinks theorem compresses many joint angles into two grouped directions. Partition the links into two straight subchains, solve the two-circle intersection problem for the grouped lengths, then unfold each group along the same direction. The notebook witness uses grouped lengths 2.6 and 1.5 and reaches the target to numerical precision.

Fixed-Direction Convex Case

But general variants can encode combinatorial choices, including Partition-style and Towers-of-Hanoi-style behavior, so the easy ordering theorem should not be mistaken for a universal planner.
