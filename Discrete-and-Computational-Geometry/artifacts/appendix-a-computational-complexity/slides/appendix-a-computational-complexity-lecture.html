Model Before Notation

In Geometry, n Must Be Named

Definition Habit

A complexity statement starts by fixing the input model: coordinates, incidence structure, comparison predicates, and the item counted by n.

  • Convex hull: points and orientation tests.
  • Triangulation: polygon vertices and diagonals.
  • Linkages: joints, links, and configuration degrees of freedom.
Slow down on the modeling step. In geometry, n is not automatically a generic list length; it might count points, polygon vertices, links, faces, constraints, or algebraic variables. A complexity claim without that convention is underspecified, because changing the encoding can change which operations and predicates are being counted.

Asymptotic Language

Ceilings, Floors, and Matched Growth

Big-O Upper Bound

T(n) ≤ C f(n)

An analyzed algorithm eventually stays below a constant multiple of the comparison function.

Big-Omega Lower Bound

T(n) ≥ c f(n)

A task or input family forces every allowed algorithm to spend at least this much work.

Theta Tight Bound

T(n) = Θ(f(n))

The constructive upper story and unavoidable lower story meet asymptotically.

This slide gives the basic asymptotic vocabulary without turning it into symbol memorization. Big-O is an eventual ceiling for a particular algorithm, Big-Omega is an eventual floor for a problem or input family, and Theta appears when the ceiling and floor match. The constants and threshold are intentionally visible because the statements are about sufficiently large n, not every small input.

Growth Ladder

Orders Become Visible on a Shared Scale

Eventual Dominance

For fixed constants, higher-order growth eventually controls the cost. The threshold may be far beyond the classroom examples.

OrderTypical geometric signal
O(n)single scan through vertices
O(n log n)sorting or balanced event queue
O(n²)all pairs, visibility matrices
2^nunstructured subset search
Read the ladder from bottom to top as eventual dominance, not as a promise about every real implementation. On the left, constant and logarithmic work barely move. In the middle, sorting-like n log n behavior stays near linear for a while. On the right, quadratic, cubic, and exponential growth quickly make brute force geometry impossible.

Constants Matter Until They Do Not

A Large Constant Can Delay the Winner

A(n) = 100 n log n
B(n) = 0.01 n²
Finite-Size Warning

The faster asymptotic class can be slower for a long practical range when its constant is large.

This example is useful because it resists a simplistic rule. A large-constant n log n algorithm can lose to a small-constant quadratic algorithm for modest sizes, especially when implementation overhead is real. Once the crossover is passed, however, the quadratic term grows faster and the asymptotic class begins to control the comparison.

Reading a Complexity Claim

Three Different Statements Often Look Similar

Claim typeWhat supplies evidence?What it does not say
Algorithm upper boundPseudocode, data structure, loop invariant, predicate count.Another algorithm may still be faster.
Problem lower boundAdversary argument, reduction, decision-tree model, information requirement.The displayed algorithm need not be optimal unless bounds meet.
Tight boundA matching upper and lower bound in the same model.Constants, cache behavior, and implementation choices disappear.
Hardness evidencePolynomial reduction from a known difficult decision problem.It is not the same as proving no fast algorithm exists unconditionally.
Instructor Prompt

When a chapter says a construction is optimal, ask: optimal among which algorithms, under which input model, and with which primitive operations?

Use the ledger language carefully. An upper bound is earned by giving an algorithm and analyzing its operations. A lower bound is earned by proving that any algorithm in a specified model has to pay a cost. A tight result is stronger than either alone because it says the algorithm's analysis cannot be asymptotically improved in that model.

Example Pattern

Convex Hulls: Construction Meets Sorting-Like Cost

Tightness Template

Upper bound: sort points, scan, and maintain a hull invariant.

Lower-bound signal: in the comparison model, hull construction can encode sorting information.

O(n log n) and Ω(n log n)
Connect this slide to familiar geometric examples. Convex hull algorithms often reduce to sorting in the comparison model, so n log n is both an achievable cost and a lower-bound signal. The important habit is to ask which model and input family support the lower bound, rather than treating the notation as a decorative label.

Algorithm Classes

P, NP, and the Certificate View

Polynomial-Time Construction

Class P contains decision problems solved directly in polynomial time.

Polynomial-Time Verification

Class NP contains decision problems whose yes-cases have efficiently checkable certificates.

Geometry Translation

A construction problem may be algorithmic, while a related existence question may be a decision problem with certificates, reductions, or real-algebraic constraints.

The left column is the constructive world: we write an algorithm and prove it halts quickly. The right column is the decision and verification world: we ask whether a certificate can be checked, or whether a known difficult problem can be translated into the new one. Geometry needs both because natural geometric questions can be easy to state and hard to solve.

Reductions

Hardness Proofs Are Directional

Reduction Rule

If A ≤p B and A is hard, then B is at least as hard as A.

  • The transformation must be efficient.
  • Yes-instances must correspond correctly.
  • The conclusion points to the target problem.
Reductions are arrows with consequences. If A reduces to B in polynomial time, then a fast algorithm for B would give a fast algorithm for A. Therefore, when A is already believed hard, B inherits evidence of hardness. The arrow direction is the most common mistake, so make students say the implication out loud.

Hardness Map

From Classic Decisions to Geometric Questions

Checklist

To claim NP-completeness, show hardness by reduction and membership by polynomial verification.

Use the diagram as a proof workflow, not a taxonomy poster. A geometric problem becomes NP-hard when known hard structure can be encoded inside it with only polynomial overhead. It becomes NP-complete only when it is also in NP, meaning proposed solutions have polynomial-size certificates that can be checked efficiently.

Geometry Adds a Model Question

Real Coordinates Can Change the Complexity Language

Encoding Caution

Some geometric decisions involve real-valued coordinates and algebraic constraints, not only finite bit strings.

  • Bit complexity asks how coordinates are represented.
  • Verification may require algebraic witnesses.
  • Guarding and visibility can leave purely combinatorial models.
This slide acknowledges a geometric wrinkle: coordinates are often real-valued, and some decision questions are naturally described by polynomial inequalities over the reals. The point is not to classify every example in the lecture, but to warn that bit encodings, algebraic certificates, and real computation models can change the right complexity language.

Applied Lab

A Workflow for a New Geometric Algorithm

Lab Heuristics
  1. Count points, vertices, links, faces, or variables.
  2. Identify sorting, sweep events, graph search, or algebraic feasibility.
  3. Record what is proven, measured, or conjectured.
Treat this as an instructor-led diagnostic. Given a new geometric algorithm, first identify what is counted, then locate the expensive operation: sorting, a sweep event queue, graph search, predicate evaluation, dynamic programming state, or algebraic feasibility. Only after that should one ask whether lower bounds or reductions are known.

Exercise

Classify a Claimed Improvement

Prompt

A polygon algorithm is advertised as faster because it beats a quadratic implementation on every test up to 20,000 vertices. Its analysis is O(n log n), but its constant factor is large.

What evidence is still missing before calling the old algorithm asymptotically inferior?

Expected Answer Ingredients

  • Define what n counts and which operations are primitive.
  • Explain finite benchmarks versus eventual bounds.
  • Ask whether a lower bound or matching analysis is known.
  • Estimate where the constant-factor crossover occurs.
This exercise is designed to make students separate practical timing from asymptotic reasoning. They should decide what n counts, compare the two plotted formulas, and explain why a finite benchmark does not prove an asymptotic bound. A strong answer mentions both the crossover and the need for a model of computation.

Takeaways

Complexity Is a Reading Discipline

Name the Model

State what the input is, how it is encoded, and which primitive operations are being charged.

Separate Evidence

Do not confuse an algorithmic upper bound, a problem lower bound, and a hardness reduction.

Respect Scale

Constants decide many real computations; asymptotics explain what survives after the threshold.

The appendix turns the course from a catalogue of constructions into a toolkit for comparing them.

Close by emphasizing the habits rather than the labels. Complexity is a disciplined way to read geometric algorithms: state the input model, distinguish algorithmic upper bounds from problem lower bounds, respect constants at moderate sizes, and use reductions when a problem seems to resist direct polynomial-time construction.
