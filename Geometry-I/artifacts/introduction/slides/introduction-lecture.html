Core Method

A Figure Is A Controlled Experiment

Four Roles To Keep Separate

  • Data: the represented object and its chosen coordinates or labels.
  • Operation: the permitted change of object, chart, frame, or parameter.
  • Invariant: the relation predicted to survive the operation.
  • Check: a visible, symbolic, or numerical witness that can fail.
\(\mathcal{L}=(D,T,I,C)\)

The tuple is not a theorem. It is a reading discipline for every visual proof attempt in the course.

Notebook vocabularyData, operation, invariant, check
Name the four roles before giving examples. Data records the object, an operation changes the object or its description, an invariant states what should survive, and a check makes the survival auditable. This vocabulary will return throughout affine, projective, Euclidean, and convex geometry.
Reading Protocol

Ask Three Questions Of Every Figure

1. What Object Is Being Acted On?

Point set, line family, triangle, projective chart, convex body, or group orbit.

2. What Operation Is Allowed?

Change a coordinate chart, apply a transformation, perturb a parameter, or sample more examples.

3. What Relationship Should Survive?

Parallelism, incidence, distance, angle, barycentric balance, cross-ratio, or supporting direction.

Inspection targetObject - operation - surviving relation
Use the three questions as a live reading protocol. Ask students to point to the acted-on object, then identify the permitted change, then name the relation that should remain stable. The diagram matters only because it lets those answers be inspected.
Translation Guide

Coordinates Are A Language, Not The Geometry

Working Warning

A point becomes an array only after a chart is chosen. A transformation becomes a matrix only after we state its domain, codomain, and coordinate basis.

\(\text{same object} \; \not\equiv \; \text{same coordinate list}\)

The notebook's repeated move is to change frames or parameters and then ask which relationship is still visible. If the relationship was only coordinate bookkeeping, it should not be promoted to geometry.

What Can Go Wrong

Three Pitfalls In Visual Geometry

Picture As Proof

A figure can reveal a proof goal, but it does not discharge the logical burden unless the construction and hypotheses are explicit.

\(\text{looks true} \not\Rightarrow \text{proved}\)

Coordinate Overtrust

A coordinate chart can simplify measurement while hiding which relationships are geometric rather than chart artifacts.

\(\text{chart change} \Rightarrow \text{test the relation}\)

Numerical Overclaim

Samples can suggest a stable quantity, but a theorem needs a reason the pattern survives beyond the sampled cases.

\(\text{evidence} + \text{argument}\)

Corrective habit: label the object, state the operation, predict the invariant, and name the check that would fail if the interpretation were wrong.

Visual cautionFigures need hypotheses and failure tests
Treat the pitfalls as mathematical failure modes. A drawing can seduce without proving, a coordinate system can hide the object, and a numerical pattern can be mistaken for a theorem. The cure is to label assumptions and decide what would fail.
Applied Lab Template

Before Proving A Definition, Build A Minimal Test

Reusable Lab Prompt

  1. Choose a later course term: group action, barycenter, cross-ratio, isometry, or supporting hyperplane.
  2. Draw the smallest object that carries the definition's data.
  3. Perturb one input while keeping the claim meaningful.
  4. Record the relation that should survive in a small check.
Lab outputOne diagram, one perturbation, one check
Turn the applied lab into a reusable template. Before proving a later definition, students choose an object, perturb one input, predict an invariant, and write a small check. This gives even abstract topics a concrete first experiment.
