The chapter's first major idea is that different objects can share the same analytic skeleton. Points, segments, triangles, rectangles, tetrahedra, and boxes differ in dimension and constraints, but closest point queries often minimize one squared-distance function over a bounded parameter set. Low-Level Numerical Issues

Floating Point Is A Model, Not The Reals

Implementation Reality
Real-number formulas enter code through a representation map \(f(r)\). Arithmetic then rounds again, so the result of a computation is not the same object as the exact formula.
A Failing Identity
Floating-point addition can satisfy $$\bigl(f(r)\oplus f(s)\bigr)\oplus f(t) \ne f(r)\oplus\bigl(f(s)\oplus f(t)\bigr).$$ Sum small nonnegative terms before large ones when accuracy matters.
Roundoff is part of the algorithm's environment3 / 10
Pause on the notation because it separates mathematical intent from machine representation. The real number r is not stored directly; the implementation stores a nearby floating point value. Once arithmetic also rounds, familiar identities such as associativity can fail, so tests must be written for the machine model rather than for ideal real arithmetic.
Stable Algebra Is A Geometric Tool

Cancellation And The Quadratic Example

Unstable Pattern
For \(a x^2+b x+c=0\), the expression $$\frac{-b+\sqrt{b^2-4ac}}{2a}$$ loses digits when \(b>0\) and \(\sqrt{b^2-4ac}\) is close to \(b\).
Stable Root Pair
Use $$q=-\frac12\left(b+\operatorname{sign}(b)\sqrt{\max(0,b^2-4ac)}\right),\qquad x_1=\frac{q}{a},\quad x_2=\frac{c}{q}.$$

Notebook sanity check: the stable quadratic residual has max error \(5.55\cdot 10^{-17}\) against tolerance \(10^{-12}\).

Stable formulas are selected, then checked4 / 10
This slide turns the classic quadratic formula warning into a graphics habit. When two nearly equal large quantities are subtracted, significant digits disappear. The stable form chooses the root formula according to the sign of b and then checks the polynomial residual, which is exactly the notebook's final sanity check.
High-Level Numerical Issues

Boolean Logic Needs Tolerance Bands

Excluded Middle Trap
A predicate may be theoretically true or false, yet the implemented tests can produce a third practical state: numerically unresolved near a boundary.
Barycentric Inspection
For a triangle, classify with $$\lambda_0+\lambda_1+\lambda_2=1,\qquad \lambda_i \ge -\varepsilon.$$ Report the tolerance band when some \(\lambda_i\) is close to zero.

Production Habit

Return more than a Boolean: include the closest feature, barycentric coordinates, tolerance, and whether the decision was strict or near-boundary.

Containment needs state, not only true or false5 / 10
Use the diagonal split as a small version of mesh point location. In exact arithmetic, a point near the shared edge belongs to one triangle or the edge case. In floating point, two triangle tests can both reject it unless the implementation records a tolerance band and reports the near-boundary state explicitly.
Robustness Policy

Degenerate Inputs Are Ordinary Inputs

Collinear And Coplanar

Hull and intersection code must decide whether nearly aligned samples become a line, a face, or a rejected degeneracy.

Cocircular

The theoretical simplification that no four points are cocircular is rarely a safe production assumption.

Rank Loss

If a coefficient or determinant is almost zero, the algorithm needs a fallback branch, not wishful division.

Design Rule
State the degeneracy policy before using the predicate downstream: exact, tolerant, symbolic perturbation, interval check, or explicit unresolved status.
Degeneracy is an input class, not an exception afterthought6 / 10
This is the high-level warning slide. Collinear, coplanar, cocircular, tangent, and almost singular cases are not rare exceptions in graphics pipelines; they occur through modeling, animation, imported data, and finite precision. The implementation plan should name the degeneracy and choose a policy before the downstream routine depends on the answer.
Root Finding And Contact Geometry

Tangency Changes The Numerical Problem

Why Bisection Can Miss Contact
A sign-changing root is easy to bracket. A tangency can produce an even-multiplicity root, where values on both sides have the same sign.
Geometric Interpretation
Transverse intersections have different tangent directions at contact. Tangential first contact has parallel tangents, so the polynomial model changes multiplicity.

The source orientation points to moving-object collision detection: the first contact time is often exactly the numerically delicate case.

Root multiplicity is contact geometry in algebraic form7 / 10
Explain that root finding is geometric, not only algebraic. A transverse intersection usually produces a sign change, so bracketing methods can see it. Tangential first contact has even multiplicity, so the sign may not change at all. Collision detection must therefore look for contact structure, not only sign reversal.
Implementation Invariant

Symmetry Is A Debugging Invariant

Segment Predicate Contract
A well-designed intersection test should satisfy $$\operatorname{TestIntersection}(S_0,S_1)=\operatorname{TestIntersection}(S_1,S_0).$$

What To Log

  • Raw orientation values before thresholding.
  • The tolerance used for zero classification.
  • Endpoint, overlap, proper crossing, or disjoint case label.
  • Whether reversing the input order changes any intermediate sign.
Input order should not change the geometric verdict8 / 10
Order dependence is a practical test for algorithm design. If a segment intersection predicate changes when the two input segments are swapped, either the mathematical cases were split asymmetrically or floating point tolerances were applied inconsistently. Treat this as a unit test because later algorithms silently assume such predicates are stable.
