Lecture route

Read the chapter as families of reductions

The source span is broad, but the notebook groups it by the computational work each query asks us to do.

Family A

Linear component against a primitive. Substitute \(X(t)=P+td\), solve for \(t\), then filter by ray, segment, polygon, or finite-solid domains.

Family B

Planar component against solids or surfaces. Use signs, edge crossings, conic sections, or local surface parameters to describe the intersection set.

Family C

Convex pair tests. Turn overlap into interval comparisons on candidate axes; a positive projection gap is the certificate of separation.

Use this map to prevent the chapter from feeling like a long list of unrelated recipes. The left column follows the source orientation, while the right column names the computational move the notebook emphasizes. Tell students that a production codebase often mixes these families, so recognizing which family they are in is already a debugging advantage.

Core invariant

Every useful query returns more than true or false

1. Representation Choose parametric, implicit, barycentric, half-space, or local-frame coordinates.
2. Solve Reduce geometry to a scalar equation, interval overlap, or sign pattern.
3. Restrict Apply the primitive domain: \(t\) range, barycentric weights, caps, slabs, or trim curves.
4. Certify Return residuals, roots, intervals, face ids, ordered vertices, or SAT gaps.
Reusable contract

\[ \text{intersection} = \text{classify}\left(\text{filter}_{D}\left(\text{solve}(R)\right)\right) \]

The domain \(D\) belongs to the primitive, not to the algebra. A line root is not automatically a ray hit, and a plane point is not automatically inside a triangle.

Minimal debug record

  • input frame and normalized directions
  • candidate parameter or root list
  • domain filter inequalities
  • residuals against all defining equations
  • classification of the returned set
Common failure

A Boolean says nothing about why a near-tangent or near-parallel case changed state under a tiny perturbation.

This slide establishes the contract we will reuse. A representation says what equation is being solved, a domain filter says which formal solutions survive the finite primitive, and a certificate explains why the answer should be trusted. Stress that a bare Boolean is often enough for speed, but it is too weak for teaching, testing, and diagnosing edge cases.

Linear component and plane

The smallest 3D intersection algorithm

Substitution

\[ X(t)=P+td,\qquad \langle n,X\rangle=c \]

\[ t=\frac{c-\langle n,P\rangle}{\langle n,d\rangle} \]

DenominatorClassificationCertificate
\(\langle n,d\rangle \ne 0\)one point on the supporting lineplane residual near zero
\(\langle n,d\rangle = 0\), numerator nonzeroparallel and disjointsigned distance is stable
both vanishline lies in the planeall sampled points satisfy plane

Rays and segments add \(t\ge 0\) or \(0\le t\le 1\) after the algebraic solve.

Walk through the line-plane equation slowly because it is the seed of the whole chapter. The denominator identifies the geometric case before the numerator gives a parameter. Once students see that parallel and coplanar behavior is a classification problem rather than a special annoyance, later degeneracies become much less mysterious.

Linear component and triangle

A plane hit still needs a triangle-domain test

Candidate point

\[ Q=P+td,\qquad t\ge 0 \]

The supporting plane supplies \(Q\). The triangle supplies the barycentric domain.

Barycentric certificate

\[ Q=uA+vB+wC,\quad u+v+w=1 \]

Keep \(u,v,w\) with the hit. They certify containment and carry interpolation weights for normals, texture coordinates, and attributes.

Edge cases

A weight near zero is a geometric statement: the ray is near an edge or vertex. Treat it as data, not as an afterthought.

Here the supporting plane gives the candidate point, and barycentric coordinates decide whether the point belongs to the triangle rather than merely to its plane. I would emphasize that the barycentric triple is both a domain test and an interpolation certificate, which is why ray tracers and collision routines keep it instead of throwing it away.

Polygons and polyhedra

After solving, most work is domain membership

Polygon route

Intersect the supporting plane, then project to a stable 2D coordinate plane and run a point-in-polygon test.

\[ Q\in \Pi,\quad \pi(Q)\in \pi(\text{polygon}) \]

Convex solid route

Represent the polyhedron as intersecting half-spaces. A line parameter survives exactly when it satisfies every face inequality.

\[ a_i \le \langle n_i,P+td\rangle \le b_i \]

ViewNatural operationWhat to return
meshedge-face crossingspoints with face ids
half-spaceclip \(t\) interval\([t_{\min},t_{\max}]\)
local frameslab inequalitiesentry and exit axes
This is the first place where mesh thinking and solid thinking diverge usefully. A polygon wants a reliable point-in-polygon test after projection, while a convex solid wants inequalities that clip a parameter interval. Students should notice that both paths are domain filters, just expressed in different coordinate systems.

Bounding boxes

Slabs convert a ray-box test into interval arithmetic

AABB slab update

\[ t_i^-=\frac{m_i-P_i}{d_i},\qquad t_i^+=\frac{M_i-P_i}{d_i} \]

\[ t_{\rm enter}=\max_i \min(t_i^-,t_i^+),\qquad t_{\rm exit}=\min_i \max(t_i^-,t_i^+) \]

Classification

Hit if \(t_{\rm enter}\le t_{\rm exit}\) and the interval intersects the ray or segment domain. A nearly zero direction component needs a parallel-slab branch.

For an OBB, transform \(P\) and \(d\) into the box's orthonormal frame, then reuse the same slab equations.

Use the box slab picture to make interval clipping concrete. Each coordinate direction contributes an allowed range of ray parameters, and the intersection survives only if the ranges have a common overlap. For an oriented box, the same idea works after transforming the ray into the box frame, so the algorithm is less special than it first appears.

Section polygon recipe

Evaluate each vertex signed distance, interpolate along crossed edges, then sort the surviving points in a basis of the cutting plane.

Certificate

All section vertices should have near-zero plane residuals, and the ordered polygon should be consistent with the face or edge adjacency used to create it.

This slide connects planar intersections to section geometry. Two nonparallel planes produce a line, three planes may produce a point or a degenerate family, and a plane cutting a polyhedron is recovered by edge crossings. I would ask students what certificate each row should return before revealing that signs, ordered vertices, and residuals play that role.

Quadrics and implicit surfaces

Line substitution turns geometry into root finding

Implicit reduction

\[ F(X)=0,\quad X(t)=P+td \quad\Longrightarrow\quad g(t)=F(P+td)=0 \]

Quadric case

\[ g(t)=at^2+bt+c \]

The discriminant classifies no real crossing, tangency, or two crossings before ray, segment, height, or cap filters are applied.

The important shift is that an implicit surface turns a geometric intersection into a one-variable root problem. The residual plot on the right is deliberately more informative than just drawing hit points. It lets students see misses, tangencies, and two crossings as changes in a scalar function after line substitution.

Cylinders, cones, and tori

Use a local frame, then let the polynomial degree guide the solver

Move the line into object coordinates. The standard equation becomes simple; the root points are transformed back afterward.

The notebook's symbolic scaffold checks degree before the numeric root routine is trusted.

Cylinders, cones, and tori are a good test of whether the unifying story is working. The line is first moved into a local frame, then substituted into the implicit equation, then filtered by height, caps, or periodic parameters. The degree column warns students about the numerical solver before they even write code.

Polynomial and free-form surfaces

When exact formulas get costly, combine bounding, refinement, and residual checks

Subdivision Split patches until simple bounds isolate possible intersections.
Lattice evaluation Evaluate a grid of control or sample data to detect candidate cells.
Analytic cases Use special structure when the equations admit a compact reduction.
Marching Trace an intersection curve from a seed while controlling step size.
Parametric surface condition

\[ X(u,v)\in \ell \quad\Longleftrightarrow\quad (X(u,v)-P)\times d=0 \]

Solving this exactly can be much harder than detecting and refining credible candidate regions.

The source span includes polynomial and free-form surfaces, where exact closed forms often give way to subdivision, lattice evaluation, analytic special cases, or marching. I would present this as a spectrum of guarantees: coarse bounding tests avoid impossible work, local refinement searches for candidates, and residual checks decide what is credible.

Separating-axis diagnostics

Convex disjointness is certified by one projection gap

SAT statement

Two stationary convex objects are disjoint if there exists an axis \(a\) whose projection intervals are separated.

\[ \max I_A(a) < \min I_B(a)\quad \text{or}\quad \max I_B(a) < \min I_A(a) \]

OBB candidate axes

For two boxes: \(A_0,A_1,A_2\), \(B_0,B_1,B_2\), and the nine axes \(A_i\times B_j\), after discarding near-zero cross products.

Certificate

A signed gap per axis. Positive means separation; negative means overlap depth along that axis.

Separating axes invert the intersection question. Instead of solving for the hit set, we search for a direction in which the projected intervals are disjoint. For oriented boxes, the fifteen candidate directions are memorable because they come from face normals and edge cross products. The useful certificate is the signed gap, not just the final yes or no.

Design prompt

For every Boolean routine, sketch the smallest certificate that would let you debug a wrong answer from one rendered frame.

This slide is about return types and software design. A point, segment, polygon, curve, or empty set should come with enough evidence for downstream code to classify contact. Encourage students to think of certificates as a debugging API: they can be plotted, asserted, compared under perturbation, and used to explain apparent rendering failures.

Robustness

Degeneracies are classification boundaries

Tolerance policy

Do not branch on exact zero in floating-point code unless the input model promises exact predicates. Name the residual, name the tolerance, and decide what ambiguous cases return.

Pause here and make the tolerance policy explicit. Exact branch diagrams are mathematically clean, but floating-point implementations see near-parallel, near-coplanar, and grazing cases. The point is not to sprinkle epsilons randomly; it is to decide which residuals are measured, which comparisons are tolerant, and what ambiguous cases should return.

Applied lab recap

A portable checklist for 3D intersection code

Five questions before coding
  • What representation makes the equations smallest?
  • What unknown is being solved for?
  • Which primitive-domain filters remain?
  • What is the possible returned set?
  • Which certificate makes the result auditable?
Lab extension

Choose one primitive pair, perturb it toward a degeneracy, and plot the certificate as the Boolean changes.

Takeaways

  • Intersections are solve, restrict, classify, and certify.
  • Parameters, barycentric weights, intervals, roots, and gaps are first-class outputs.
  • Polyhedra need both mesh and half-space viewpoints.
  • Polynomial degree predicts the numerical work ahead.
  • Diagnostics make degeneracies inspectable before they become bugs.
Close by turning the lecture back into a lab habit. For any primitive pair, students should write the representation, solve the reduced equation, filter to the primitive domain, classify the returned set, and preserve the certificate. That five-part checklist is portable across the entire chapter and is the best antidote to memorized intersection snippets.
